# 信息架构与页面规范

本文件描述目标结构，路径清单依据 2026-10-24 当前 `app.json`。默认保留现有路由，不用重命名页面目录解决视觉问题。

所有页面均采用 01 已确认的官方蓝色色系：主行动与选中态用品牌主蓝，常规导航保持白底深字。首页、维修组和“我的”不再分别使用独立蓝色主题；正式品牌展示按 01 选择横版或方形标志。

## 1. 顶层导航与角色

| 身份 | Tab 顺序 | 首页重点 | 维修组区域 |
| --- | --- | --- | --- |
| `user` 普通用户 | 首页／报修／我的 | 去报修、当前报修进度、服务说明 | 不显示 Tab；直达内部页面需权限拦截 |
| `member` 组员 | 首页／维修组／报修／我的 | 我的任务、今日值班、报修入口 | 日常任务、值班、志愿、工作量与工具 |
| `leader` 组长 | 同组员 | 与组员一致，管理摘要按真实权限显示 | 日常功能＋管理入口；只管理允许的对象 |
| `admin` 管理员 | 同组员 | 同内部成员，以实际能力为准 | 管理入口必须以权限规则与服务端能力判定 |

角色入口须与 `app.checkPermission`、业务 action 和后端授权一致；不能用 `role === 'leader'` 代替完整的角色层级判断，视觉入口不能创造权限。

权限变化时刷新角色与可操作能力，移出成员回到普通用户导航，清理不能再访问的内部缓存与未执行操作。不能只改 Tab 文案。

## 2. 四个一级页面

**首页：服务与当前事项。** 顶部简短品牌标题；第一组为“报修设备”主行动和服务提示；第二组为可点击的当前事项；内部成员可看到自己的值班摘要。团队风采与特色活动置于任务信息之后，保留真实内容，但不靠自动轮播占据首屏。数据来源不足时不伪造工单总数、服务时间或预计修复时长。

**维修组：成员工作台。** 首先展示真实可获得的待处理事项／个人值班摘要，然后是日常功能；管理功能单独分组且只对有权者展示；手册、软件库等工具靠后。没有聚合接口时先展示静态功能入口，不为凑工作台装饰去新增统计接口。页面自然滚动，不能以 `overflow:hidden` 隐藏小屏内容。

**报修：一个连续任务。** 搜索与分类进入同一向导；阶段内保留返回和已选摘要；费用说明在选择问题与最终提交前可见；完成后立即提供“查看报修进度”。表单按钮默认在内容流中，不与 TabBar 争夺底部。

**我的：个人身份与服务记录。** 头像、姓名、角色、部门；分组展示我的待办、消息、关于；未读数与待办数语义明确。退出放在页面末尾或独立次级入口，不能占据身份卡主要位置。部门切换是业务操作，需显示冷却与成功／失败结果。

## 3. 页面模板

| 模板 | 从上到下的结构 | 必需状态 |
| --- | --- | --- |
| P0 启动／身份 | 品牌与明确等待 → 登录／注册表单 → 状态结果 | 加载、失败重试、身份失效 |
| P1 一级工作台 | 顶栏 → 核心行动／我的事项 → 功能与内容 → TabBar | 模块加载、模块失败、普通／内部角色 |
| P2 列表／管理列表 | 原生导航 → 搜索／筛选 → 数量／条件 → 列表 → 分页反馈 | 首载、空、筛选空、刷新、追加失败 |
| P3 详情 | 原生导航 → 名称与状态 → 时间／人员／关键内容 → 记录 → 操作 | 无权限、已删除、数据更新、操作处理中 |
| P4 表单／编辑 | 导航 → 分组说明 → 字段 → 校验 → 主次按钮 | 草稿、修改未保存、校验失败、提交结果 |
| P5 统计 | 导航 → 时间范围与口径 → 总览 → 图表与文字数据 → 更新／导出 | 0 数据、缺失、加载、过期、导出失败 |
| P6 值班 | 导航 → 周与日期 → 编辑状态 → 日程表／可读列表 → 个人选择 → 确认 | 锁、冷却、冲突、已确认、跨周 |
| P7 内容／外链 | 导航 → 内容／访问说明 → 明确打开／复制动作 | 图片失败、分页失败、跳转失败 |

二级详情有固定操作栏时，内容必须留出实际占位。只读详情不强行放一个空操作栏。

## 5. 导航与上下文

- 导航集中通过 `router`；Tab 用 `switchTab`，普通页面用既有路由封装。不要给 `switchTab` 拼接 query，当需要分类预选时用既有状态通道并在消费后清理。
- 每个列表保留搜索、筛选和滚动位置，详情返回后更新受影响条目；不能每次返回都跳回顶部。
- 通知直达详情必须带可验证的记录标识；记录删除／权限变化时提供返回列表，冷启动仍经过启动守卫。
- 从分类地图回报修时带回已选分类，保留仍适用的表单内容。不能打开地图后丢失原来的填写进度。
- 全页横滑切 Tab 默认移除。值班表局部横滚保留，原生返回手势不改为应用自定义手势。
- 详情不能以“我的待办”与“维修任务”两个入口发展为两套视觉；保留角色差异的操作，复用相同信息结构。

## 6. 文案口径

使用“你”或省略主语，称呼和标点全局统一。状态固定使用 02 的映射；不把“已结束”写成“已完成结算”。时间默认按北京时间明确展示，需要跨日时写日期；“今天 14:00”须同时可获得完整日期。历史时间不能只显示不稳定的“刚刚”。

费用使用已有业务配置中的说明，不擅自承诺“全部免费”；维修预约不等于承诺修复时限。`user` 对外称普通用户，内部 `member/leader/admin` 对应组员／组长／管理员，不能给管理员显示“组员”兜底。
