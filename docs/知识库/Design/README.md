# 维修组小程序设计规范

版本：1.1 · 建立／更新日期：2026-10-24 · 品牌色已按官方标志确认 · 适用范围：原生微信小程序前端。

本目录是后续界面改造的设计基线。目标是让报修同学快速完成报修、让成员准确处理任务、让管理人员清楚理解操作影响，同时让不同页面看起来属于同一个产品。

**交付状态：规范已建立，界面尚未按新规范改造。** 现状判断来自当前工作区的代码审查，没有进行真机视觉审查、用户访谈或可用性测试。文中的布局、尺寸与流程是下一阶段的目标，不代表现有功能已经支持。

## 已确认的品牌方向

用户提供的横版与方形官方标志共同确定品牌主蓝为 **`#0369D7`，RGB(3, 105, 215)**。两张原始 JPG 的最高频背景色完全一致；取色依据及完整蓝色色阶见 01 与 `design-tokens.json`。此前暂定的交互蓝已被本次确认值替代，不再作为另一套可选方案。

界面使用“官方品牌蓝＋白色内容面＋蓝灰中性色”；主按钮、选中态、链接和维修类图表统一沿用此蓝色色系。成功、警告和危险仍使用独立语义色，不把所有业务状态染成蓝色。品牌与用色规则已确认，页面流程与真机实现仍按既定计划验收。

## 规范如何生效

1. 实现前阅读根目录 `AGENTS.md` 和本目录，再使用项目级 `ui-ux-pro-max` Skill 查阅补充建议。
2. 本目录确定产品设计；Skill 的搜索结果仅供参考。业务事实以云函数、数据库初始化器及已确认的业务文档为准，不由视觉规范改变。
3. 颜色数值以 `design-tokens.json` 为准；语义与使用方法以 01、02 为准。修改其中一处时，同步另一处和验收记录。
4. 新页面复用模板与组件。例外必须在对应变更中写明原因、影响页面和退出条件，不能默默新造一套样式。
5. 修改布局时连同加载、空、失败、无权限、长文本和键盘态一起评审，不能只评审理想截图。

## 不变的业务边界

- 角色层级为 `user < member < leader < admin`，导航与权限沿用 `router`、`app.checkPermission` 和服务端校验。
- 启动页继续承担登录守卫；页面不能为简化体验而绕过身份验证。
- 云函数调用只走 `apiAdapter`。重试不等于服务端幂等，离线排队也不等于提交成功。
- EWA 权重为维修 0.5、志愿 0.4、值班 0.1；单科目上限 300，不改变现有计量口径。
- 值班每周预选最多 3 段，确认后不可自行撤销；锁、冷却和部门切换冷却必须保留。
- 组员管理遵循 [现有业务说明](../../member-management.md)：保留移出原因、交接阻塞、权限范围、版本校验和历史工作量。
