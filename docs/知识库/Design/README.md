# 维修组小程序设计规范

版本：1.2 · 更新日期：2026-10-24 · 适用范围：原生微信小程序前端。

本目录仅保存可复用的设计范式：视觉语言、组件职责、页面结构、交互合同、界面质量与 Skill 使用规则。规范描述目标要求，不代表现有页面已经符合全部要求。

产品定位为“清晰、可信、有温度的校园服务工具”：报修同学能完成报修与查看进度，成员能准确处理任务，管理人员能理解操作影响。

## 品牌与规范优先级

官方横版与方形标志共同确认主蓝为 **`#0369D7`，RGB(3, 105, 215)**。界面使用官方品牌蓝、白色内容面和蓝灰中性色；成功、警告、危险使用独立语义色。官方标志保持原比例与蓝底白图形，不重新选蓝、不重绘标志。

业务事实以云函数、数据库初始化器及已确认业务文档为准；权限和业务规则优先于视觉建议。设计值以 `design-tokens.json` 为准，语义与使用方法以 01、02 为准，两者须保持一致。外部 Skill 只提供补充建议，不生成第二套设计基线。

页面和组件须同时符合正常、加载、空、失败、无权限、长文本与键盘等适用状态要求。特殊布局须注明原因和适用范围，不能形成页面自选主题。

## 不变的业务边界

- 角色层级为 `user < member < leader < admin`，导航与权限沿用 `router`、`app.checkPermission` 和服务端校验。
- 启动页承担登录守卫，页面不能绕过身份验证。
- 云函数调用只走 `apiAdapter`；重试不等于服务端幂等，离线排队不等于提交成功。
- EWA 权重为维修 0.5、志愿 0.4、值班 0.1，单科目上限 300。
- 值班每周预选最多 3 段，确认后不可自行撤销；锁、冷却和部门切换冷却必须保留。
- 组员管理遵循 [业务说明](../../member-management.md)，保留移出原因、交接阻塞、权限范围、版本校验和历史工作量。
