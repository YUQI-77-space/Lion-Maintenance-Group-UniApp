# 设计语言与视觉规范

设计定位：**清晰、可信、有温度的校园服务工具**。品牌方向已按用户提供的官方标志确认：以 `#0369D7` 为唯一主蓝，配合浅灰页面、白色内容面、深色正文和克制的状态色。所有页面共用一套语义 Token。

## 1. 视觉层级

页面依次回答“我在哪／当前是什么状态／有哪些关键信息／接下来能做什么”。标题、状态和主操作优先于装饰图。常用任务页不使用满屏渐变、大面积描边、叠层阴影、发光或玻璃滤镜。

首页可使用真实团队照片，但应位于服务入口之后或保持紧凑。文字不能直接放在对比度不可控的照片上；需要叠加时，采用足够不透明的独立信息底面并验证合成结果。装饰图片不能承担唯一导航含义。

## 2. 颜色

最终数值见 [design-tokens.json](design-tokens.json)。`--mg-*` 为本规范的语义变量命名；JSON 为设计值，不是可直接导入的 WXSS。

### 2.1 官方品牌来源与蓝色色阶

品牌主蓝：**`#0369D7`／RGB(3, 105, 215)**，来自用户提供的两张原始官方 JPG，而非聊天缩略图或屏幕截图。分别对原图解码后的 RGB 像素做频次统计，主背景色完全相同。此值确定为小程序使用的数字品牌色；以后有正式矢量源文件及色值时，再核对版本，而不是重新凭审美选择另一种蓝。

| 色阶 | 色值 | 角色与边界 |
| --- | --- | --- |
| Blue 50 | `#F2F8FD` | 轻提示、选中区域浅底；文字用主蓝或更深蓝 |
| Blue 100 | `#E6F0FB` | 较明显的选中浅底、浅色品牌区；不用白字 |
| Blue 200 | `#CDE1F7` | 装饰边线、浅色图表背景；不能单独作为必要控件边界 |
| Blue 300 | `#9AC3EF` | 次要图形、低强调可视化；不作正文色 |
| Blue 400 | `#4F96E3` | 图形与辅助数据系列；不用于白字主按钮或小字链接 |
| Blue 500 | `#0369D7` | 官方主蓝，主按钮、选中 Tab、链接、当前步骤、维修图表 |
| Blue 600 | `#035CBD` | 主按钮按下态；白字 |
| Blue 700 | `#0250A3` | 强调链接、信息状态文字、浅蓝底上的重要说明 |
| Blue 800 | `#023F81` | 品牌说明区的深色标题，少量使用 |
| Blue 900 | `#012A56` | 极少量深色品牌信息区；不替代全局浅色模式 |

这些是同一主色的 UI 衍生色，不是十种并列主色。50／100／200／300／400 分别将主蓝按 5%／10%／20%／40%／70% 与白色混合；600／700／800／900 分别保留 88%／76%／60%／40% 主蓝并与黑色混合。按 sRGB 通道数值计算，四舍五入到整数；该方法用于稳定复现，不代表等感知明度。

颜色规则：

- 一个页面的常规行动只有一个强调色；状态色用于表达状态，不用于装饰不同模块。
- 普通文本对背景的对比度目标至少 4.5:1；有意义的图标与必要控件边界至少 3:1。大字也优先遵守 4.5:1，减少规则分叉。
- 状态标签采用深色文字＋同语义浅底＋明确状态词；不能只用红绿圆点。
- 品牌浅底使用品牌深色文字；警告浅底使用警告深色文字；不在亮黄或浅绿底上放白字。
- 禁用态采用次级底色与辅助文字，不对整个控件统一降低 opacity，以免文字不可读。
- 遮罩、图片覆盖文字及透明色必须测合成后对比度，不能只测前景十六进制值。

按标准 sRGB 相对亮度公式计算，Token 文件列出的组合中：品牌蓝＋白字为 5.242:1，按下态蓝＋白字为 6.423:1，主蓝＋Blue 50 浅底为 4.898:1，辅助文字＋Blue 100 浅底为 4.534:1，控件边界＋白底为 3.654:1。均达到各自目标；实际应用出现新组合时要重新检查。

### 2.3 页面与组件中的用色约定

- 主按钮固定 Blue 500＋白字，按下为 Blue 600；次按钮保持白底和中性边框，不增加第二种品牌色。
- 链接、选中 Tab、当前步骤用 Blue 500；选中项底面用 Blue 50 或 Blue 100，并增加主蓝勾选／边线或明确文字，不只靠浅底区分。
- 顶部栏与 TabBar 默认白底深字，选中态和小面积品牌元素用主蓝。启动页和正式品牌展示区可以采用官方蓝底白标，不把所有业务页改为整页蓝底。
- 待办、任务详情、表单继续使用白色内容面，品牌蓝用来提示行动与选择；背景、边界和正文使用已有蓝灰中性色。
- 进行中与一般信息采用 Blue 700＋Blue 50；成功绿、警告棕黄、危险红及中性灰保留独立语义。不能把“已完成”和“错误”也统一成蓝色。
- Blue 200–400 不作小号文字或白字按钮底。浅蓝底与白底的差异不是必要边界，输入框仍使用独立的 `control-border`，焦点用主蓝。
- 页面品牌用色属于这套色阶，不使用紫蓝、靛蓝和另一种亮蓝作为各页面自选主题。

## 3. 中文字体与数字

使用系统中文无衬线字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。不加载 Google Fonts 或在线字体。常规字重 400，强调 500，标题 600；不让全页都变成粗体。

| 层级 | Token | 字号／行高 | 场景 |
| --- | --- | --- | --- |
| 展示数字 | `display` | 48rpx／60rpx，600 | EWA 总值；同屏最多一组 |
| 页面标题 | `title` | 40rpx／56rpx，600 | 一级页主标题 |
| 区块标题 | `section` | 34rpx／48rpx，600 | 卡片／分组标题 |
| 正文／表单 | `body` | 30rpx／46rpx，400 | 输入内容、说明、列表标题 |
| 标签／元信息 | `label` | 28rpx／40rpx，400 | 字段名、时间、步骤 |
| 辅助信息 | `caption` | 24rpx／36rpx，400 | 次要单位、计数、短标签 |

以上按 750rpx 设计基准定义；320px 小屏不能简单缩到看不清。正文实际至少 15px，例如先设 `font-size:15px`，再按已验证的基础库能力使用 `font-size:max(15px,30rpx)`；不支持时保留像素回退，不能使用不存在的 `min-font-size` 属性。不要给文字容器写死高度；大字体允许换行，关键按钮文字完整显示。

任务标题列表最多两行，详情完整展示。日期、金额、状态、错误与费用说明不得省略。纯数值右对齐，单位紧邻数值，精度与后端一致；EWA 默认最多两位小数，去掉无意义尾零，缺失用“—”，不能把缺失当 0。

## 4. 尺寸、布局与间距

`rpx` 用于随屏幕变化的布局；系统状态栏、胶囊和安全区测量值保持 `px`，禁止直接与 `rpx` 相加。750rpx 基准下，375px 宽屏 2rpx≈1px，这不是所有设备上的固定换算。

| 项目 | 标准 |
| --- | --- |
| 间距刻度 | 8／16／24／32／48／64rpx；4rpx 仅用于细微标签对齐 |
| 页边距 | 32rpx；紧凑表格例外 24rpx |
| 内容面内边距 | 32rpx；紧凑列表项 24rpx |
| 区块之间 | 32rpx；明显章节间 48rpx |
| 标签到输入 | 12rpx；帮助与错误到输入 8rpx |
| 按钮高度 | 标准 96rpx，紧凑 80rpx；触控热区仍按下述标准兜底 |
| 输入／选择行 | 最小 96rpx；多行文本最小 192rpx |
| 通用点击热区 | 至少 48px×48px；用 `min-height/min-width` 或外层 padding 兜底 |
| 独立热区间隔 | 目标至少 8px；小图标扩大热区后不能互相重叠 |
| 表单布局 | 手机单列；长页按含义分组，不横向滚动 |

48px 热区是本项目的统一实现目标，不等同于原生 iOS 的 pt、Android 的 dp 或 WCAG 的最小网页尺寸。320px 宽屏上仅写 88rpx／96rpx 均可能不足，必须验证实际像素尺寸。

## 5. 圆角、边框、图标与图片

- 内容卡／弹窗 24rpx；按钮／输入 16rpx；小标签 8rpx；头像与紧凑胶囊用完整圆角。大面积内容不使用全胶囊外形。
- 分隔线默认 1px，必要时使用设备适配细线；边框只用于区分边界，不把所有内容都框起来。
- 默认不用阴影；仅浮层和确需区分的固定操作栏使用一层弱阴影，Token 为 `0 8rpx 24rpx rgba(24,34,48,0.08)`。
- 功能图标统一为线性、圆角端点、相同视觉粗细，24px 设计稿使用约 2px 描边。导航选中态主要靠品牌色＋文字／选中标记，不能任意替换为另一套图形。
- 图标布局尺寸 32／40／48rpx；热区与图标尺寸独立。结构性图标禁用 Emoji，品牌标识保持原比例。
- 沿用 `iconManager`、`cloudImageManager`、`avatarManager`。可使用已有可控 PNG；如新增资源，先验证微信 `image` 支持的格式与目标机型，保留经过验证的 PNG 回退，不强行要求运行时 SVG。
- 头像 64／88／120rpx；列表封面统一 4:3，内容展示图默认 16:9。图片缺失时保留尺寸，显示中性占位与替代说明。
- `miniprogram/images/` 等被忽略的资源目录只写接入要求，不伪造可用素材或外链。

### 官方标志使用

原始横版 `物科院维修组 (2).jpg` 约为 4:1，适用于启动、关于、服务说明等可完整展示品牌名称的位置；`方形.jpg` 为 1:1，适用于方形品牌块或应用身份展示。保持原图比例、官方蓝底及白色图形／文字，不拉伸、裁掉齿轮或线路，不增加渐变、描边、阴影，也不对 Logo 应用按钮按下滤色。

保留原图内已有留白，排版净空目标至少为可见标志图形高度的 1/8；已有留白可计入。不能为缩小文件而先裁去必要留白，或将方形图强行裁成圆形导致线路被切断。小尺寸下，横版文字不可辨认时使用合适的方形版本与独立系统字体标题，不替换／重排原标志中的专用字形。

当前文件为带底色 JPG，不视为透明资源。需要透明底、深色图形或其他正式变体时从原始设计源文件导出并重新确认，不自动抠图、重新描绘或直接用 CSS 滤镜造出未批准的标志。品牌参考原图与运行资源分开管理，运行资源遵循现有图片管理链路。

## 6. 导航、安全区与层级

一级 TabBar 为贴底白色底面，内容高度 56px＋底部安全区；4 个或 3 个入口等分，图标与文字始终同时显示。顶部栏用状态栏高度、微信胶囊位置动态计算，不能照抄 44px 或固定刘海高度。

使用受支持的 `wx.getWindowInfo()`／`wx.getMenuButtonBoundingClientRect()` 获取窗口、`safeArea` 和胶囊信息，旧基础库按项目兼容目标回退；安全区内缩须根据窗口坐标口径计算，不能同时叠加测量值和 `env(safe-area-inset-bottom)`。缺失信息按无额外安全区处理并保留标准栏高，随后进行真机验证。

底部占位规则：

- Tab 页：滚动内容底部至少留出 TabBar 实际总高＋16px。
- 有独立固定操作栏的二级页：留出操作栏实际总高＋16px，操作栏本身包含安全区。
- 报修中间步骤优先使用内容流内按钮，避免在 TabBar 上再叠一层固定按钮；若真机需要固定操作栏，放在 TabBar 上方且合并计算占位。
- 键盘弹出时保证当前输入、错误和确认操作可见；按实际 `adjust-position`、键盘高度和滚动位置处理，不用双重位移。

层级采用内容 0、吸顶 100、底部操作 200、TabBar 300、遮罩 900、弹窗 1000、应用内提示 1100。平台原生导航、键盘、弹窗和原生组件不受这个 WXSS 数字完整控制，必须验证实际遮挡关系。

## 7. 动效

按下反馈 100ms；选择切换 160ms；浮层出现／关闭 220ms。只做轻微透明度或小距离位移，不对全页做逐卡错峰入场。避免动画 `width/height`、持续闪烁、发光和后台运行动画。

首屏信息即时可见，不为动效等待；加载时间由真实请求决定，不人为延迟。提供无动效版本，能读取系统减少动效偏好时遵循它；无法检测时默认使用克制动效。自动轮播默认关闭，确需轮播时必须可暂停且不承载必读说明。

## 8. Token 与样式作用域

同一语义使用同一 Token。兼容别名的目标关系见 `design-tokens.json` 的 `legacyAliases`；别名不能形成另一套设计值。

自定义组件遵守微信样式隔离规则，不假定 `app.wxss` 类名能够穿透组件。Token 的引用方式必须受目标基础库支持，组件内外的同语义表现应一致。按钮的文字、边界、背景和按下态须作为完整组合符合规范。
