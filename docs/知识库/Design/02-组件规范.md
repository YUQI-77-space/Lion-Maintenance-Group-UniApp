# 组件规范

本规范同时约束外观与行为。01 提供尺寸与颜色，本文定义何时使用、状态如何转换。文中的 `mg-*` 表示规范命名，不代表仓库已有同名可调用组件。

品牌用色已确定：主操作、链接、当前步骤和选中 Tab 使用官方主蓝 `#0369D7`；按下态使用 `#035CBD`，选择浅底使用 `#F2F8FD`／`#E6F0FB`。直接复用 01 与 Token 的语义映射，不在组件中另造蓝色。成功／警告／危险继续保持各自语义色。

文字层级统一遵守 01 的固定 px Token：常规按钮与表单输入 15px、字段标签／次要操作／图标下的入口名称／搜索输入与提示 13px、状态与计数 12px、弹窗／区块标题 16px。按钮大小变体不放大文字，点击热区仍至少 48px；组件隔离内显式接入 Token 和系统字体。

## 1. 复用策略

优先顺序：微信原生能力 → 已有公共组件 → 公共样式 → 新建小型组件。相同结构至少在两个页面重复、且需要相同状态行为时再考虑封装。只有样式相同的容器用 WXSS 类，不为每个矩形建组件。

尽量避免“容器套容器”的视觉效果：同一组信息或入口只保留一层必要的可见底面，优先用留白、间距、文字层级和分隔组织内容。不在大卡片内再用带底色、描边或阴影的小卡片重复包裹同一操作；纯布局容器保持透明。确有独立交互或语义分组需要时才保留内层容器。

首页快捷入口使用紧凑、彼此分离的圆角区域，布局外层不设共同底色或边框，图标不再另套可见底框。“我要报修”仅用品牌蓝文字强调，不增加第二层高亮容器。入口圆角采用 32rpx（此类短入口的明确例外），独立点击热区至少 48px×48px，间隔目标至少 8px；压缩高度不能牺牲文字完整性与点击范围。

| 组件／样式 | 职责与表现 | 行为边界 |
| --- | --- | --- |
| `avatar-display` | 头像尺寸、失败占位和替代说明 | 数据与图片加载继续沿用现有链路 |
| `entry-item` | 作为功能入口行／网格的基底 | 导航由父页经 `router` 统一处理；组件与父页不能对同一次点击分别跳转 |
| `search-field` | 统一 SVG 放大镜、灰色占位、胶囊圆角输入与清空 | 分发输入／确认／清空／焦点事件；搜索、筛选与分页逻辑由父页负责 |
| `section-header` | 统一标题、“查看全部”与计数 | 不再由每个页面另做标题布局 |
| `action-modal` | 确认弹窗与底部抽屉 | 已有 `visible/loading/disabled/danger/bottom`；不绕过外层控制的业务校验 |
| `feedback-modal` | 业务职责独立，外观遵守公共弹窗规则 | 包含已读与订阅相关逻辑，不能简单替换为展示组件 |
| `loading-animation` | 统一双方块交错上浮翻转，用于初始化、按钮、分页及刷新 | 列表已有数据时不覆盖全页；页面隐藏暂停，减少动效时静态展示 |
| `loading-overlay` | 业务等待弹层，复用统一动画、说明与可选遮罩 | 由 `utils/loading` 的 `show/hide` 控制；页面隐藏或卸载时清理，保留防重提交逻辑 |
| `skeleton-image` | 图片比例固定，等待时保留同尺寸静态骨架，提供失败回退 | 图片独立完成即展示，加载失败必须结束等待 |
| `.btn`、`.list-item`、`.form-*`、`.tag` | 公共样式及其语义变体 | 原生 `button/input/picker/textarea` 优先；复杂状态才封装 |
| 页面级空／错误／加载块 | 区分加载、空、错误和无权限；共用时可采用 `mg-page-state` 命名 | 建议字段 `kind/title/description/actionText`，事件 `retry/action` |
| 重复任务卡／固定操作栏 | 相同信息结构共用样式，业务行为独立 | 业务按钮权限留在页面和服务端，不能隐藏在纯视觉组件里 |

## 2. 按钮与链接

| 变体 | 表现 | 用途 |
| --- | --- | --- |
| Primary | 品牌色实底、白字 | 提交报修、确认值班、保存修改；当前任务区域最多一个 |
| Secondary | 白底、控件边界色描边、主文字 | 返回修改、取消编辑、查看其他内容 |
| Text | 无底、品牌色文字 | 查看全部、修改分类等低频附属操作 |
| Danger | 危险色实底、白字 | 最终删除／移出确认层；详情页危险入口优先文字形式 |

状态必须覆盖 `default / pressed / disabled / loading`；成功后导航到结果或更新当前内容。加载态保留按钮宽高，仅显示统一加载动画，隐藏动作文案和“正在提交”等重复提示，不可重复触发；提交防重锁应在第一段异步操作前生效，包括订阅授权前。

禁用与加载都必须有真实的事件守卫或原生 `disabled`，不能只有灰色。因冷却、锁定、权限或名额导致不可用时，在附近常驻显示原因；不能让用户点击后才猜测。

同层双按钮：左侧次要、右侧主要；短文字可同行，文字变长时纵排且主按钮优先可见。正文链接不得仅靠颜色区分，可加箭头或明确动作词。不能使用“确定”代替“确认移出”“提交报修”等具体动作。

## 3. 表单、搜索和选择

每项包含永久可见标签、输入／选择控件、必要时的帮助与错误。占位文案只是例子，不承担标签；选填字段标“选填”，必填标识由表单开头统一说明。

- 普通输入：姓名、联系方式、型号；键盘类型按字段设置，允许粘贴与修改。
- 长文本：故障描述、移出原因；显示字数上限，限制和接口保持一致，不在视觉层擅自新增限制。
- 枚举：原生 `picker` 或少量可见选项；值班等多状态场景用专门列表，不塞进通用下拉。
- 日期时间：显示完整日期与时间，校验预约可用性；不以默认值假装用户已经确认。
- 图标功能入口：首页快捷入口、维修组功能宫格及 `entry-item` 的名称使用 label 13px／20px，常规字重 400，主入口最多 500；辅助描述使用 caption 12px／18px，不按正文或标题放大名称。
- 搜索：统一复用 `search-field`（`/components/search-field/index`），左侧本地 SVG 放大镜，右侧原生输入与框内灰色提示文字，圆润胶囊圆角、单层白色底面；不另设“搜索”文字按钮或 Emoji 图标。可见框高 40px，外层及输入／图标／清空保留至少 48px 热区；输入和灰色提示均为 label 13px、常规字重 400，图标 16px。输入、提示垂直居中，输入区允许收缩；SVG 加载失败使用原生搜索图标回退。组件提供 `value/placeholder/label/maxlength` 属性及 `input/confirm/clear/focus/blur` 事件，事件值为 `detail.value`；清空只发 `clear`，父页恢复原列表并保留其他筛选。点击放大镜与键盘搜索均发 `confirm`；即时搜索、防抖、请求失效与分页仍由父页负责。即时搜索可 300ms 防抖，只渲染最新响应，不清除用户身份。
- 筛选：维度不超过两项时用轻量选择器，更多维度放抽屉；显示已选条件和“重置”，空结果提供“清除筛选”。筛选不得改变数据库状态。

校验顺序为输入格式 → 当前步骤必填 → 提交时完整校验 → 服务端业务校验。输入过程中不反复弹 Toast。提交失败滚动到首个错误项并在字段下显示具体原因，多处错误另给摘要；通过微信支持的能力提供焦点与读屏反馈，不直接照搬 DOM 的 `role=alert` 或锚点 API。

切换分类时只清除不再适用的字段，其余填写内容保留。需要清除已填关键内容时说明影响并确认。提交失败、权限恢复失败、网络错误均不应无故清空表单。

## 4. 卡片、列表与功能入口

**任务列表项**：标题＋状态；问题分类／活动类型；预约或活动时间；受理人／负责人；必要时当前用户下一步。信息最多三组，详情放入详情页。单号为次要信息，需要时提供复制热区，不能抢占标题。

整行导航时使用一致箭头或“查看详情”提示，按下有反馈。若含独立操作，必须用 `catchtap` 等微信事件机制阻止冒泡；不能一次点击同时打开详情和提交操作。

**入口行**用于“我的”等设置／功能集合：图标、名称、简短说明、计数、箭头。**入口网格**只用于维修组稳定的少量功能，图标不使用各色背景作为主要分类方式；手机默认 2–3 列，以名称不拥挤和热区达标为准。不能把业务任务也压成没有说明的九宫格。

**详情信息组**：标题后跟状态摘要；标签与值对齐，长值换行，联系方式与单号可复制。费用、预约与当前受理情况不折叠；历史日志等次要信息可折叠，展开入口必须可见。

## 5. 状态与步骤

业务状态和界面状态分开。不要把 `loading`、`offline` 写进任务业务字段。

| 业务 | 现有值／表达 | 展示语义 |
| --- | --- | --- |
| 维修 | `pending` 待受理 | warning |
| 维修 | `inProgress` 进行中 | info |
| 维修 | `completed` 已完成 | success |
| 维修 | `cancelled` 已取消 | neutral；保留后台已有状态值 |
| 志愿 | `pending` 待发布 | neutral；仅有权查看者可见 |
| 志愿 | `inPreparation` 筹备中 | info |
| 志愿 | `inProgress` 进行中 | info；使用文字区分筹备 |
| 志愿 | `ended` 已结束 | neutral；不暗示每个成员都已结算 |
| 值班 | 可选／预选／已确认／已排／操作中／不可选 | 交互展示态，保留现有后端字段；锁定原因和所属人独立展示 |

状态映射同时输出文字与语义 Token，工具函数、页面与 WXSS 的同一业务状态含义必须一致。后端状态优先，前端时间推算只能做待刷新提示，不能赋予操作权限。

步骤条只展示用户理解的阶段：报修为“选择问题 → 填写信息 → 核对提交”。内部三级分类属于第一阶段，不显示为三个独立大步骤。已完成阶段允许返回修改；未来阶段不能通过点击跳过校验。不能只用细线颜色表示完成，要有文字／图标说明。

## 6. 弹窗、抽屉与通知

| 需求 | 采用形式 | 内容与关闭规则 |
| --- | --- | --- |
| 简单二选一确认 | `wx.showModal` | 标题、对象、后果；取消明确，普通操作不额外确认 |
| 多步核对／有原因输入 | `action-modal` 自定义弹窗 | 保留上下文、字段错误和提交进度；成员移出属于此类 |
| 编辑资料／筛选 | 底部抽屉 | 单一任务，内部可滚动、底部按钮可见，支持键盘 |
| 轻量成功反馈 | Toast | 例如“已复制”；不承载长说明或唯一结果 |
| 持续错误／离线／缓存过期 | 页内提示条 | 原因、影响、重试；恢复后消失 |
| 报修成功／关键流程完成 | 页内结果区 | 明确完成内容、后续安排和主要去向 |

系统 `wx.showModal` 保留平台外观，规范统一它的文案和触发条件；不能为追求像素一致替换所有原生弹窗。

自定义弹窗宽度受小屏限制、正文内部滚动；焦点与读屏名称按基础库支持设置。遮罩和返回不能在提交中误关闭。未修改的编辑可直接关闭，已修改则提示“放弃未保存修改？”；取消后保留编辑。普通底部抽屉允许点遮罩关闭，最终危险确认层不以误触遮罩完成或绕过步骤。

纯展示弹窗仅需收起时，使用右上角叉号，不再设置占据底部整行的“关闭”按钮。叉号保留至少 48px×48px 热区、明确的关闭读屏名称和按下反馈，标题为其预留空间。涉及取消编辑、返回修改、确认收到、提交或危险决策的按钮仍按业务含义保留，不以叉号代替必要确认；微信原生弹窗沿用平台外观。

自定义多层浮窗最多一层业务弹窗；订阅授权与待反馈弹窗串行出现，避免叠加抢焦点。`feedback-modal` 不因统一样式丢失原有消息确认逻辑。

## 7. 加载、空、错误、离线

能用排版和动效清楚传递的信息，不再增加重复文字。需要动画反馈的加载态（全局等待、页面初始化、分页、刷新、按钮与设置进度）仅呈现统一动画，不显示“加载中”“提交中”等可见提示；按钮空闲时恢复动作名称，保留原有尺寸及防重逻辑。保留供读屏使用的无障碍标签；错误、风险、恢复操作及需要用户决策的信息仍明确说明。

同一页面、同一次加载尽量只保留一处主加载动画；不叠加全局、区域和逐图动画。图片使用固定尺寸的静态骨架，头像使用现有轮廓占位，完成后各自展示；首页多图片板块和相册详情复用此方式。已有内容刷新保留内容，只显示顶部刷新反馈；分页请求仅在底部显示一处动画，不给已展示的图片追加等待动画。

| 界面状态 | 表现 | 可用行动 |
| --- | --- | --- |
| 首次加载且没有缓存 | 同布局骨架或整页加载；约 300ms 内完成的请求可不闪现骨架 | 返回／切 Tab；不能永远锁住导航 |
| 已有内容刷新 | 保留内容，区域刷新提示 | 原有安全的查看操作；过期敏感写操作需刷新确认 |
| 真实空数据 | “还没有报修记录”等具体说明 | 权限允许时“去报修” |
| 筛选为空 | “没有符合条件的任务”＋已选条件 | “清除筛选” |
| 请求失败且无缓存 | 错误说明＋“重新加载” | 不显示为“暂无数据” |
| 请求失败但有缓存 | 保留旧内容，显示“显示上次内容”与更新时间 | 重试；不宣称实时 |
| 离线 | 常驻离线说明，保留已读内容和未提交草稿 | 网络恢复后由用户核对关键写操作 |
| 权限不足／记录删除 | 说明变化并提供返回去向 | 不无限重试、不展示“服务繁忙” |
| 已到列表末尾 | “已显示全部” | 不再发起下一页 |

分页沿用 `page/pageSize/hasMore/loadingMore`。追加失败只在列表底部显示重试；失败不自增页码；刷新清理并发旧响应。刷新使用项目现有 `onRefresherRefresh` 约定，不同时触发两套刷新。

## 8. 图表与数据

EWA 三科使用固定映射：维修使用官方主蓝 `#0369D7`、志愿 `#19734A`、值班 `#8A5700`。这只是图表分类色，不等同于业务状态；同一维修数据系列不再使用旧蓝色或额外紫蓝色。

- 对比／排名优先横向柱图，按数值排序；很多成员时分页或筛选，不挤出数十根细柱。
- 未来如需恢复三类构成图，可使用饼图，但需同时给名称、原始值、加权贡献和比例；0 总量时不画空扇形或除以 0。
- 原始工作量图与加权贡献图分开标注口径。不能用原始值比例当作 EWA 总分贡献比例。
- Canvas 外提供可读文字列表或表格，点击取值不作为唯一获得信息的方法。
- 同页单位、精度、时间范围和数据更新时间一致；缺失、真实 0、计算失败分别展示。

## 9. 组件验收最小集

每个可交互组件至少检查：默认、按下、禁用、处理中、失败恢复、长文字、缺失数据、小屏、系统大字体、读屏标签。与固定底栏／键盘相关的组件额外检查安全区、滚动与焦点；不是所有纯展示组件都要加没有意义的交互状态。
