# 落地计划与验收规范

当前阶段只建立规范与项目 Skill。下述为后续实施计划，不是已经完成的改造清单。无根 lint／test／build 脚本；小程序界面验证通过微信开发者工具与真机完成。

品牌前提已经确认：使用官方标志的 `#0369D7` 及 01 定义的同源色阶。批次 A 直接按已确认 Token 落地，不再把选蓝色、重绘标志或从 Skill 重新生成色板作为待决策事项。

## 1. 分批改造

| 批次 | 内容 | 开始前条件 | 完成门槛 |
| --- | --- | --- | --- |
| A 基础 | 语义 Token、旧变量别名、按钮／表单／状态、导航和安全区；统一 `action-modal` 视觉 | 读取本目录与当前工作区改动 | 公共样例覆盖状态与长文案，样式隔离验证通过；全局变更逐页抽查 |
| B 报修与维修闭环 | 报修、分类地图、待办、维修列表／详情／管理／创建 | A；核实创建／受理／完成的真实权限、幂等与返回 ID | 从普通用户报修到成员处理，再回到用户进度完整跑通 |
| C 一级与身份 | 首页、维修组、我的、启动／登录、消息；替换 TabBar，移除全页横滑 | B 形成可复用的事项卡与反馈方式 | 普通／内部导航稳定、角色切换正确、安全区一致、原任务上下文可恢复 |
| D 内部复杂业务 | 值班、志愿、EWA、组员管理及相关个人详情 | A–C；核实锁、冷却、参与方式、版本与计量规则 | 并发冲突、待交接、权限失效、0 数据和修改恢复均有真实验收记录 |
| E 内容与收口 | 团队风采、特色活动、关于、更多、手册／软件；清理死样式与旧变量 | 前批组件稳定 | 31 页纳入同一套规范；资源失败和外链失败有合理去向 |

先交付一条能验收的完整任务，再扩展到其他页面。先新增并验证兼容映射，再迁移消费者，最后删除旧规则。不要同时更换全部变量与业务实现，导致回归难以定位。

## 2. 每个实施任务的交付内容

1. 目标用户、入口、主要动作与成功去向。
2. 页面结构与复用组件，新增部分的必要性。
3. 正常、加载、空、失败、禁用、过期／离线、无权限状态；不适用项说明原因。
4. 涉及的 action、角色限制、业务状态、幂等与缓存失效范围。
5. 实际截图／录屏与验收记录，写明设备、微信／基础库版本、角色、操作、预期、实际。
6. 仍未实现的能力和后续依赖；不得把仅存在的按钮当成功能完成。

建议在本目录后续新建 `验收记录/YYYY-MM-DD-模块.md`，截图使用不含真实成员隐私的测试数据。含成员资料的记录放到 Git 忽略目录，不提交个人信息。

## 3. 视觉与可访问性检查

- [ ] 所有普通文字对比度至少 4.5:1；有意义图标与必要控件边界至少 3:1；透明底、图片底按实际组合验证。
- [ ] 页面颜色来自语义 Token；例外为受控图表／真实图片／品牌资源，不能随手新增十六进制色。
- [ ] 主品牌色、主按钮与选中 Tab 对应 `#0369D7`；深浅变体属于同一官方蓝色色阶，旧页面蓝已按批次迁移，无另一套可选品牌蓝。
- [ ] 官方标志比例、蓝底白图形与净空符合 01；不裁切线路、不重绘、不对 Logo 应用渐变或按下滤色，带底 JPG 不被当成透明图。
- [ ] 同层级字体、间距、圆角、图标粗细一致；主要行动清晰，没有多个实心强调按钮竞争。
- [ ] 所有独立点击热区实际至少 48px×48px；图标本体可小于热区；相邻热区不重叠。
- [ ] 长标题、长姓名、双位数／99+徽标、费用长说明、极端数值不挤压主要动作。
- [ ] 标题和关键状态不靠颜色识别，Canvas 提供文字数据，图标按钮有读屏名称。
- [ ] 系统大字体时关键内容完整可达；不能以固定高度裁切中文或错误说明。
- [ ] 表单有永久标签；输入错误可定位、可理解；提交失败不丢失填写内容。
- [ ] 内容不被顶部胶囊、TabBar、操作栏、底部手势条或键盘遮挡；安全区只计算一次。
- [ ] 点击有即时反馈，加载态不重复提交；无故障时不强制等待动效。

## 4. 设备与场景矩阵

| 维度 | 最低覆盖 |
| --- | --- |
| 视口 | 开发者工具约 320／375／430 CSS px 宽度；记录实际窗口尺寸 |
| 真机 | 至少一台带底部手势区的 iPhone、一台 Android；包含较低性能设备或性能模拟 |
| 微信环境 | 当前线上最低支持基础库与当前版本；记录具体版本，不只写“最新版” |
| 字体与辅助 | 系统大字体、VoiceOver／TalkBack 基础操作、无动效版本 |
| 网络 | 正常、慢网、断网、请求超时、恢复网络 |
| 身份 | user／member／leader／admin，以及登录失效／运行中权限变化 |
| 数据 | 无记录、仅一条、多页、超长文字、真实 0、字段缺失、记录已删除 |

v1 主要验收竖屏手机。横屏／平板至少检查导航不遮挡、内容可滚动、弹窗可关闭；大屏专用重排可另列后续任务，不宣称已完整适配。

## 5. 必须完成的业务验收场景

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| R01 | 普通用户搜索问题、填写、返回改分类、再提交 | 适用内容保留，动态字段正确，费用提示同步，生成一条真实报修 |
| R02 | 拒绝／部分接受订阅授权 | 核心报修继续，最终结果明确 |
| R03 | 连点提交、请求超时后重试 | 提交锁有效；服务端幂等／结果核实成立，不制造重复任务 |
| R04 | 报修成功后回首页和待办 | 对应信息刷新，条目能进入正确详情 |
| M01 | 两位成员同时尝试受理同一任务 | 按后端结果确定唯一有效状态；冲突者看到最新受理人 |
| M02 | 任务完成／取消后从两个入口查看 | 业务状态与允许操作一致，EW 不由前端重复入账 |
| D01 | 预选达到上限后继续选择、再正式确认 | 保留有效选择，说明限制，确认前展示不可自行取消 |
| D02 | 时段被锁、被占用、编辑关闭、触发冷却 | 每种情况有具体原因与可用恢复行动 |
| D03 | 确认时跨周／后台切周 | 不把旧选择写入新周，不离线盲目重放 |
| V01 | 负责人选择参与者／用户查看参与状态 | 不出现未实现自助报名；活动状态和个人状态不混淆 |
| E01 | 维修 100、志愿 50、值班 20 的测试数据 | 原始值正确，总分 72，图表口径明确 |
| E02 | 无数据、真实 0、缺失字段、更新失败 | 三种结果分开，失败提供重试，禁止编造 0 |
| U01 | 组长、管理员、本人、不同目标角色进入成员详情 | 入口与服务端 permissions 一致，禁止越权 |
| U02 | 修改资料时后台更新版本／触发部门冷却 | 显示冲突／恢复时间，保留草稿，不覆盖新资料 |
| U03 | 移出有未交接事项的成员 | 显示阻塞与去向、保留原因，不自动取消业务 |
| U04 | 确认移出后重新登录 | 普通账号、历史与工作量保留；旧权限不能复活 |
| N01 | 从消息进入已删除或无权限记录 | 解释变化，能返回列表，不无限重试 |
| N02 | 断网后阅读缓存、恢复网络、切换身份 | 缓存更新时间可见，旧身份草稿／队列不越权重放 |

只对真实改变的业务逻辑运行已有相关测试；没有根测试命令，不新建一套只验证颜色常量的测试。界面和交互要求不能以纯 Node 测试替代真机检查。

## 6. 可用性验证与指标

邀请 3–5 名未参与开发的同学试做“首次报修、查看进度、选值班、找到任务”；管理流程由有对应职责的人试做。先记录基线，再对比改造后数据，不虚构改善比例。

| 指标 | 记录方式 | 初步目标 |
| --- | --- | --- |
| 报修完成率 | 无口头帮助完成／参与人数 | 小样本至少 4/5 完成，作为问题发现目标而非统计结论 |
| 关键入口发现 | 首次寻找报修／进度／值班的时长和误点 | 一次观察内能找到，持续记录耗时与错误路径 |
| 数据保留 | 返回、失败、恢复网络后的填写内容 | 不发生无说明丢失 |
| 并发与重复 | 测试环境检查最终记录与业务结果 | 不重复新建、不越权、不错误结算 |
| 主观清晰度 | 让用户复述当前状态与下一步 | 能正确说明，而不是仅评价“好看” |

埋点不是本轮前置工作。可先用人工测试表记录，避免为度量界面改造引入额外后端与个人信息采集。

## 7. 发布与回退

后续实现先在开发者工具及测试环境验证，再按项目现有方式预览／上传。云函数是否需要改动由幂等、权限、字段和返回能力审查决定，不能为纯视觉改造批量部署后台。

每批保留可回退的前端变更边界；涉及成员身份安全、移出标记、幂等和业务校验的后台修复，不能随视觉回退一起撤销。回退后仍需保证旧入口能访问正确业务记录与权限。

## 8. 完成定义

某批完成意味着页面结构、组件外观、全状态交互、权限和数据一致性均通过该批适用的验收场景，并有实际记录。只完成规范、Token 文件、静态稿或默认态截图，不等于完成小程序改造。
