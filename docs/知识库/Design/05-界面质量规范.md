# 界面质量规范

本文件规定界面质量门槛、验证覆盖和业务结果要求，不规定改造顺序、排期或发布步骤。本文与 01–04 共同构成设计范式；单张默认态截图不能证明界面合格。

## 1. 视觉与可访问性要求

- [ ] 所有普通文字对比度至少 4.5:1；有意义图标与必要控件边界至少 3:1；透明底、图片底按实际组合验证。
- [ ] 页面颜色来自语义 Token；例外为受控图表／真实图片／品牌资源，不能随手新增十六进制色。
- [ ] 主品牌色、主按钮与选中 Tab 对应 `#0369D7`；深浅变体属于同一官方蓝色色阶，页面无另一套可选品牌蓝。
- [ ] 官方标志比例、蓝底白图形与净空符合 01；不裁切线路、不重绘、不对 Logo 应用渐变或按下滤色，带底 JPG 不被当成透明图。
- [ ] 同层级字体、间距、圆角、图标粗细一致；主要行动清晰，没有多个实心强调按钮竞争。
- [ ] 符合 [结构引导与文字克制](03-信息架构与页面规范.md#7-结构引导与文字克制)：通过分组、组件、空间关系和反馈识别当前状态与下一步，不依赖密集小字或重复教程；必要说明在相关决策点可见，不靠缩字或低对比度降低视觉存在感。
- [ ] 所有独立点击热区实际至少 48px×48px；图标本体可小于热区；相邻热区不重叠。
- [ ] 长标题、长姓名、双位数／99+徽标、费用长说明、极端数值不挤压主要动作。
- [ ] 标题和关键状态不靠颜色识别，Canvas 提供文字数据，图标按钮有读屏名称。
- [ ] 系统大字体时关键内容完整可达；不能以固定高度裁切中文或错误说明。
- [ ] 表单有永久标签；输入错误可定位、可理解；提交失败不丢失填写内容。
- [ ] 内容不被顶部胶囊、TabBar、操作栏、底部手势条或键盘遮挡；安全区只计算一次。
- [ ] 点击有即时反馈，加载态不重复提交；无故障时不强制等待动效。

## 2. 验证覆盖要求

| 维度 | 最低覆盖 |
| --- | --- |
| 视口 | 开发者工具约 320／375／430 CSS px 宽度；记录实际窗口尺寸 |
| 真机 | 至少一台带底部手势区的 iPhone、一台 Android；包含较低性能设备或性能模拟 |
| 微信环境 | 当前线上最低支持基础库与当前版本；记录具体版本，不只写“最新版” |
| 字体与辅助 | 系统大字体、VoiceOver／TalkBack 基础操作、无动效版本 |
| 网络 | 正常、慢网、断网、请求超时、恢复网络 |
| 身份 | user／member／leader／admin，以及登录失效／运行中权限变化 |
| 数据 | 无记录、仅一条、多页、超长文字、真实 0、字段缺失、记录已删除 |

主要目标为浅色模式的竖屏手机。横屏／平板的基本要求是导航不遮挡、内容可滚动、弹窗可关闭；满足这些要求不等于已完成大屏专用布局。

## 3. 业务交互质量场景

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| R01 | 普通用户搜索问题、填写、返回改分类、再提交 | 适用内容保留，动态字段正确，费用提示同步，生成一条真实报修 |
| R02 | 拒绝／部分接受订阅授权 | 核心报修继续，最终结果明确 |
| R03 | 连点提交、请求超时后重试 | 提交锁有效；服务端幂等／结果核实成立，不制造重复任务 |
| R04 | 报修成功后回首页和待办 | 对应信息刷新，条目能进入正确详情 |
| M01 | 两位成员同时尝试受理同一任务 | 按后端结果确定唯一有效状态；冲突者看到最新受理人 |
| M02 | 任务完成／取消后从两个入口查看 | 业务状态与允许操作一致，EW 不由前端重复入账 |
| D01 | 预选达到上限后继续选择、再正式确认 | 保留有效选择，说明限制，确认前展示不可自行取消 |
| D02 | 时段被锁、被占用、编辑关闭、触发冷却 | 每种情况有具体原因与可用恢复行动 |
| D03 | 确认时跨周／后台切周 | 不把旧选择写入新周，不离线盲目重放 |
| V01 | 负责人选择参与者／用户查看参与状态 | 不出现未实现自助报名；活动状态和个人状态不混淆 |
| E01 | 维修 100、志愿 50、值班 20 的测试数据 | 原始值正确，总分 72，图表口径明确 |
| E02 | 无数据、真实 0、缺失字段、更新失败 | 三种结果分开，失败提供重试，禁止编造 0 |
| U01 | 组长、管理员、本人、不同目标角色进入成员详情 | 入口与服务端 permissions 一致，禁止越权 |
| U02 | 修改资料时后台更新版本／触发部门冷却 | 显示冲突／恢复时间，保留草稿，不覆盖新资料 |
| U03 | 移出有未交接事项的成员 | 显示阻塞与去向、保留原因，不自动取消业务 |
| U04 | 确认移出后重新登录 | 普通账号、历史与工作量保留；旧权限不能复活 |
| N01 | 从消息进入已删除或无权限记录 | 解释变化，能返回列表，不无限重试 |
| N02 | 断网后阅读缓存、恢复网络、切换身份 | 缓存更新时间可见，旧身份草稿／队列不越权重放 |

业务结果以真实接口与最终数据为依据。纯 Node 测试、颜色常量检查和开发者工具截图不能替代真机界面及交互验证。


## 4. 合格判定

页面结构、组件外观、适用状态、权限和数据一致性必须同时符合规范。未验证项须明确标记，不能默认为通过。验证证据须包含设备、微信／基础库版本、窗口尺寸、角色、操作、预期与实际结果；截图使用脱敏测试数据。敏感个人资料不得进入公开或可提交的验证记录。
