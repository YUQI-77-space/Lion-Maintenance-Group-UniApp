# 值班周次校准与部署验收

## 已核对的官方说明

核对日期：2026-10-23。实现沿用项目的 `wx-server-sdk ~2.6.3`，不升级依赖。

- [腾讯云：定时触发器说明](https://cloud.tencent.com/document/product/583/9708)：七段 Cron，定时器使用异步调用，事件包含 TriggerName。触发器只负责唤醒，不应把每次唤醒等同于业务周次加一。
- [腾讯云：错误类型与重试策略](https://cloud.tencent.com/document/product/583/41138)：定时触发属于异步调用，可能重试，业务需要保证重复执行安全。
- [腾讯云：数据库事务](https://cloud.tencent.com/document/product/876/48442)：服务端支持事务、提交和回滚；文档锁及写冲突用于保护并发修改。事务内只使用按 ID 访问文档，不使用 where 查询。
- [腾讯云官方 Node SDK：数据库说明](https://github.com/TencentCloudBase/node-sdk/blob/master/docs/database/database.md)：serverDate 是写入时由数据库解释的服务端时间标记，不能当成可立即读取的日期。业务周次用云函数的 Date.now() 显式换算北京时间，审计字段用 db.serverDate()。

## 原因与处理

原自动逻辑按“配置周的周一 10:30”决定执行，然后把 currentWeek 加一；配置已是本周时，仍可能提前进入下一周。6 天去重只约束自动执行，不能统一处理手动操作和并发。原切周还存在先检查后覆盖写入、部分写入后误认为整周已存在的风险。

本次保留 autoWeekSwitcherTimer 的每周一 10:30 Cron 和 autoSwitchEnabled 开关。唤醒后计算实际自然周，只追赶落后的周次，不自动回退超前周次；未到本周一 10:30、不在学期第 1～20 周内均不前进。重复触发不再累加。

“值班设置 → 日期校准 → 校准本周”先展示云端北京时间日期、目标周及周一至周日范围。确认时再次计算日期，并核对预览时的开学日、当前周次和学期年份；期间相关配置变化或跨周时拒绝执行，要求重新预览。

校准和手动切周把缺失时段与当前周配置放入同一事务。已有时段不覆盖，不删除其他周，不改排班人员、锁、待办或 EWA；ID 对应的日期/学期/周次异常时整次中止。回滚失败或通信异常时，应刷新核对结果后再操作，不能仅凭客户端超时判断是否已提交。

校准只修复当前周指针，不会把未来周的人员迁移到本周。开学日错误、历史日期错写、错误周已确认的排班需要组长核查，不自动重写。原有“设置开学日”“重置本周数据”等功能仍具有自身的数据维护语义，不能用它们代替本次校准。

维护接口通过微信上下文的 OPENID 查询 users 角色，只允许 leader/admin。updateDutyConfig 不再允许直接写当前周、年份和自动执行审计字段。首页改用完整日期匹配今天，日期不匹配时提示联系组长校准，且不再把已过去的星期循环列为下一段。

## 本地验证

在仓库根目录执行：

```powershell
node --test cloudfunctions/dutySchedule/weekSafety.test.js
```

测试不连接云端。覆盖北京时间周界、10:30 边界、开关、重复触发、手动与自动并发、落后追赶、超前保护、跨年、预览过期、跨周确认、写入中断回滚、权限与伪造触发器、已有业务数据保留、首页日期匹配。另通过实际安装的 wx-server-sdk 拦截传输层验证事务 API 与数据序列化兼容。

## 部署和云端验收

本次没有连接生产环境、部署云函数或校准现有数据库。需要使用微信开发者工具验收：

1. 在独立测试云环境备份并复制 duty_config.global 及相关测试时段、待办。先上传部署 dutySchedule（云端安装依赖），再预览修改后的小程序。保留现有两个触发器的名称、Cron 与启用状态，不运行 initDataBase、清空或重新生成值班表。
2. 用组长进入校准，核对实际开学日与目标日期，先取消一次，确认没有写入；再执行校准。验证原周与目标周已有人认领的时段、待办、工作量及编辑开关不变，首页日期一致。
3. 在测试环境重复调用自动任务、先手动切到本周再触发自动任务，确认仍为本周；验证自动关闭时无更新，以及周一 10:30 的真实触发日志。普通成员直接请求校准、切周、更新配置必须失败。
4. 用两个测试客户端并发操作；一方冲突时应提示刷新重试，不应出现半张表或人员被覆盖。核对云函数实际执行耗时低于云端超时配置；前端请求预算为 30 秒，无法代替云端超时设置。
5. 测试环境验收后，再发布生产云函数和小程序；首次生产校准仍必须核对预览日期。回滚代码前先核查当前周配置，不要恢复旧版“无条件向下一周累加”的逻辑后立即重放触发事件。
