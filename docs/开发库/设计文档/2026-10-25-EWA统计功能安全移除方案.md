# EWA 统计功能安全移除方案

创建日期：2026-10-25。状态：已完成本地源码调查，以下为建议方案，尚未实施移除、部署或云端验证。

后续状态：本地移除已按本方案实施，实际变更与验证见 [EWA统计功能移除与验证](../开发日志/2026-10-25-EWA统计功能移除与验证.md)。下文保留调查时的方案及验证边界。

## 1. 结论与范围

移除对象是 EWA 的「工作量统计」子页：团队累计加权总分、成员数、加权贡献及占比、原始工作量表格和统计刷新。保留 EWA 排名、前三名领奖台、成员工作量调整、重新汇总和 Excel 导出。

当前统计页没有专用后端 action：它分页调用 `equivalentWorkloadAssessment.getRanking`，再通过前端 `ewaDisplay.summarize` 汇总。后端没有可以随该页面单独删除的统计接口、集合或部署单元。安全完成前后端移除的结果应是：删除统计页的整条专用调用链，保留仍服务其他业务的后端能力，云端无需变更。

不能按 `summary`、`统计` 等词批量删除。`updateSummary` 是工作量重新结算，`ewaSummary` 是业务成绩记录；两者均不是统计子页的专属资源。

## 2. 图表为什么消失

本地 Git HEAD 的 `summary/index.json` 注册了 `pie-chart`、`bar-chart`；当前工作区已删除注册，页面改为构成条、列表与表格。因此这是呈现方式被改写，并非已证明存在图标资源加载故障。

[首次重做记录](../开发日志/2026-10-24-EWA排名与统计界面重做.md) 明确记载移除该页饼图与 Canvas 柱图调用；[二次重构记录](../开发日志/2026-10-25-EWA排名与统计界面二次重构.md) 进一步改为单条堆叠构成条。本次不恢复图表，按最新需求规划完整下线。

| `cloudfunctions/equivalentWorkloadAssessment/` | 排名、结算、调整与导出共用后端 | 保留整个云函数及其 action、权限和响应结构，无统计专用模块可删 |

| `ewaSummary`、初始化器、索引与业务写入 | 维修、志愿、值班、成员维护与导出均依赖 | 全部保留；不迁移、不清空、不重算数据 |

旧 Canvas 组件没有外部调用的结论来自当前可检索的本地源码；不代表已核查线上全部历史版本或被忽略的本地材料。

## 4. 后端与数据保护边界

实际链路为：统计按钮 → 统计页 → `getRanking` 全分页读取 → 前端汇总。排名页本身也使用 `getRanking`，工作量编辑使用 `updateUserEW`，重新汇总使用 `updateSummary`，导出 action `exportExcel` 实际分发到 `exportAdvancedExcel`。

另外已查到以下共享依赖：

- 维修的 `maintenanceEWManager.js`、值班的 `dutyEWManager.js` 写入 `ewaSummary`。
- 志愿活动的工作量设置、状态更新及删除逻辑读取或修改该集合，并有跨云函数计算调用。
- `users/ensureEwaSummary.js`、`users/memberManagement.js` 负责成员成绩记录创建或姓名同步。
- `initDataBase` 创建集合与索引，Excel 导出读取既有成绩记录。

因此本次不删除后端接口、不撤销成员读取权限、不修改结算公式、不调整数据库安全规则，也不删除导出文件或云图片。没有数据库写入，就无需执行数据迁移或为下线另行触发「重新汇总」。后续若扩大为移除整个 EWA 系统，应重新调查，不能沿用本方案。

## 5. 测试与文档同步

`tests/design-remaining.test.js` 当前有三组仅服务被删除能力的测试：汇总函数的加权值／缺失值、统计全分页及失败保留、统计占比与零值。实施时删除对应测试，并新增明确的下线断言：统计路由、按钮、跳转方法和专属导出均不存在；所有注册页面文件仍完整。不能通过删掉管理功能断言来获得通过。

`number`、`format` 的零值、空字符串、缺失、非法值回归仍需保留或补充，继续验证管理保存取消不写入、缺失不能自动保存为零、刷新队列与缓存、数据菜单权限与忙碌守卫。

同步更新：

- `README.md`：删除统计页目录说明，以及饼图、柱图、Canvas 图表库和双轨统计展示等已不成立的现状介绍；保留排名、公式和 Excel 导出说明。
- `docs/知识库/Design/03-信息架构与页面规范.md`：删除统计页映射。
- `docs/知识库/Design/02-组件规范.md`：组件清单中不再把已删除的图表组件描述为现有能力；通用数据表达原则可以保留。
- 前端重构优化计划：标注统计子页及专属图表的阶段任务因本次需求终止，关联新的实际实施记录；保留历史阶段结果，不改写旧验收事实。
- 历史开发日志、历史截图和证据保留；实施完成后新建开发日志说明变更与实际验收，不将本文提前标为已完成。

全局设计 Token 的 `chart` 色彩定义属于设计基线，本次不因页面下线联动删除。

## 6. 安全实施顺序与回退

1. 固定本次实施前的相关文件快照。当前工作区已有大量未提交改动，涉及 EWA 页面、公共组件、测试和文档；不能用 `git reset` 或整仓回退覆盖它们。快照应包含相关未跟踪文件。
2. 一次性删除路由、入口、页面、专属汇总代码及无引用绘图组件，再清理专用样式和更新测试、文档。避免只隐藏按钮、仍保留可直达页面。
3. 完成下列验收后，以正常小程序版本发布交付；不部署或删除云函数。旧客户端继续使用共用后端，避免前后端版本切换破坏旧版本。
4. 回退时只恢复本次快照涉及的代码、路由、测试和文档，不触碰业务数据。恢复基线应为移除前工作区，而非较早的 Git HEAD。

新版本不保留可访问的统计空壳。旧路径在新包中应不可进入；实施时检查已有分享配置和启动路径，必要时沿用现有启动守卫的失效路径处理。历史安装包中已包含的统计页不会因新版本删源码即时消失，本次不为强制封禁旧页而破坏共用排名接口。
