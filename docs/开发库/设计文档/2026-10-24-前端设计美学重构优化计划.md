# 前端设计美学重构优化计划

建立日期：2026-10-24。适用技术：原生 WXML／WXSS／JS、自研 Canvas、现有 TCB 云函数。**本文为执行指南，当前实施与验收状态见第十五节；代码实现不等于阶段验收通过。**

目标是让 31 个注册页面形成统一、清楚、克制的校园服务体验，同时保留报修、任务、值班、志愿、工作量和成员管理的全部业务约束。视觉基线沿用官方主蓝 `#0369D7`、白色内容面、蓝灰中性色、系统中文字体和轻量交互，不重新选品牌方向。

## 一、执行依据与计划边界

规范入口：[Design README](../../知识库/Design/README.md)。视觉值看 [01](../../知识库/Design/01-设计语言与视觉规范.md) 与 [Token](../../知识库/Design/design-tokens.json)，组件看 [02](../../知识库/Design/02-组件规范.md)，页面模板看 [03](../../知识库/Design/03-信息架构与页面规范.md)，流程看 [04](../../知识库/Design/04-关键交互流程.md)，质量与场景编号看 [05](../../知识库/Design/05-界面质量规范.md)。现状依据见 [审查记录](../审查文档/2026-10-24-前端现状审计与设计决策.md)，其代码结论须在开工时复核。

- 只以原生小程序实现，不引入前端框架、在线字体、网页图表库或复杂动效库，不搭建新的通用设计系统平台。
- 保留路由名、四级角色、启动登录守卫、`apiAdapter`、现有图片管理链路和数据口径。页面美化不授予新权限，不改变数据库结构。
- EWA 固定为维修×0.5＋志愿×0.4＋值班×0.1，单科目上限 300；值班每周预选最多 3 段、确认后不可自行撤销，锁与冷却必须保留。
- 前端可调整呈现、事件绑定、输入恢复和反馈；发现服务端幂等、返回 ID、授权或并发保障不足时，先形成有证据的独立修复项，不能把后台改造混进换肤。相关安全与正确性条件不满足时，该流程不能验收完成。
- 不默认添加附件、自助报名、统计接口、跨会话草稿或深色主题。已有能力足够时复用；确需新增能力时单列范围与依赖。
- 本文不授权云资源部署、数据库写入或线上发布。实施时使用项目已有测试／预览流程；真实敏感写操作使用可控测试对象。

## 二、顺序、依赖与拆分原则

按“单页局部 → 组件复用 → 全局样式 → 导航结构 → 数据呈现 → 普通写流程 → 管理写流程 → 并发调度 → 全量清理”推进。介入层级、覆盖范围和潜在影响逐步扩大；这不是按文件数量或工时机械排序。最后的清理覆盖全局，须等所有消费者迁移后再做。

| 阶段 | 计划 | 侵入与主要风险 | 前置条件 | 可独立交付的最小范围 |
| --- | --- | --- | --- | --- |
| 0 | 建立基线与回归清单 | 不改运行代码 | 阅读规范与当前改动 | 路由、截图、状态与调用链基线 |
| 1 | 展示页局部精修 | 最低；局部样式与排版 | 0 | 关于页一个完整页面 |
| 2 | 可复用视觉基础 | 低至中；共享组件影响消费者 | 1 的样例通过 | 一组样式＋一个展示组件 |
| 3 | 全局 Token 与样式兼容 | 中；全局继承与旧类名冲突 | 2 | Token 接入及一组别名映射 |
| 4 | 一级页面与导航外壳 | 中至高；角色、手势、安全区 | 3 | TabBar 与四个一级页面外壳 |
| 5 | 列表、详情与统计呈现 | 高；多页状态、导航与数据解释 | 4 | 一个列表与对应详情，保留写行为 |
| 6 | 身份、报修与维修闭环 | 更高；表单、重复提交与跨页同步 | 5 | 一条可核实的报修到处理路径 |
| 7 | 内部管理操作与抽屉 | 高风险；权限、版本、计量与移出 | 6 | 单一模块的完整管理路径 |
| 8 | 值班调度与并发交互 | 最高业务风险；锁、冷却、跨周 | 7 | 成员预选到正式确认，再做管理 |
| 9 | 全量收口与兼容清理 | 最大覆盖；删除共享规则的连带影响 | 1–8 的适用项通过 | 一组经证明无消费者的旧规则 |

阶段按表依次推进，不把高风险流程提前混入展示页提交。每阶段内部按子步骤串行验收；一次提交围绕一个可回退目标，样式、导航和业务逻辑尽量分开。未改造页面可以暂时保留旧局部表现，但不能因新全局规则出现不可读、遮挡或操作失效。

下文“允许改动”是阶段边界；确需越界时，先在该阶段记录具体原因、影响和新增验收项，再拆出单独变更。不能用越界例外取消权限或业务质量门槛。

## 三、阶段 0：基线与回归准备

**目标：** 清楚知道页面现状与影响面，让后续每批都有可比较的证据。此阶段不改页面。

**执行步骤：**

1. 检查工作区已有改动，记录当前版本及需保留的未提交内容；不覆盖与本任务无关的变更。
2. 从 `miniprogram/app.json` 重新核对路由与 Tab；本计划基线为 31 页、4 个配置 Tab，普通用户实际显示 3 个。
3. 阅读 `app.js`、`utils/apiAdapter.js`、`router.js`、`outbox.js`、`network.js`、`swrCache.js` 和图片管理器。登记每条待改流程的 action、角色、业务状态、重试、缓存和返回 ID 来源，不在文档写凭证或权限码。
4. 盘点 `styles/variables.wxss`、`common.wxss`、`custom-navbar.wxss`、`app.wxss` 的导入与消费者，及 8 个顶层公共组件目录。扫描颜色时包含 WXSS、WXML 行内样式、JS Canvas／状态映射和 JSON 配置，不以单个十六进制数量评判质量。
5. 在开发者工具记录代表页正常、长文本、空、失败态；在 iPhone／Android 建立安全区与键盘基线。尚无设备的项标“未验证”，不写通过。
6. 建立测试角色与脱敏数据：user、member、leader、admin；包括一条、多页、真实 0、缺失值、删除记录及版本冲突对象。

**允许改动：** 开发库中的基线／审查记录。**禁止：** 改运行样式、部署云函数、修复历史数据或批量升级工具。

**验收标准：** 路由表与实际配置一致；每个待改模块有负责人可执行的入口与结果路径；共享样式和组件消费者可追溯；截图注明设备、窗口、角色与版本。缺口均标明阻塞哪些阶段。

**回退边界：** 仅文档，可直接修订；不得把基线截图中的现状写成目标规范。

## 四、阶段 1：展示页局部精修

**目标：** 用最容易回退的页面确定文字、留白和内容面的真实效果。

**执行步骤：**

1. 先改 `pages/user/about/index`：收敛品牌区高度，统一标题、正文、联系方式与复制行层次；使用规范页边距、行高、圆角和弱分隔，保留官方标志比例。
2. 样例通过后，依次处理 `pages/home/team-spirit/index`、`special-events/index`：统一封面比例、标题行数、正文宽度和列表间距，图片失败保留占位，不改分页来源。
3. 再处理 `pages/team/home/more/index`、`pages/team/manual/index`、`pages/team/software/index` 的静态入口和访问说明，保留既有外链打开／复制方式。
4. 本阶段只在页面作用域使用 Token 中的确切设计值；需要局部变量时沿用规范命名，下一阶段抽到共享文件，不能另建色板。已有错误／加载分支只改善呈现，不新增请求逻辑。

**允许改动：** 上述页面的 WXML、WXSS，必要的页面标题配置和展示字段；既有事件保持含义。**禁止：** 修改 `app.wxss`、全局变量、公共组件默认行为、`router`、云函数、数据及服务承诺。发现费用说明矛盾时单列核实，不借美化擅自承诺免费。

**验收标准：**

- 关于页先独立通过再复制范式；六页的标题、正文、图片和复制入口符合 01、02。
- 320／375／430px 下无非必要横滚、文字裁切和图片跳动；系统大字体可读；独立点击热区实际至少 48px×48px。
- 原复制内容、外链目标、分页与返回行为保持正确，图片失败不会永远显示骨架。
- 无关页面的默认截图没有因本阶段发生变化。

**回退边界：** 按单页回退，不影响全局样式与业务数据。

## 五、阶段 2：可复用视觉基础

**目标：** 把阶段 1 的稳定视觉沉淀为小规模复用能力，避免复制出多套实现。

**执行步骤：**

1. 以 JSON 为参考新增 `miniprogram/styles/design-tokens.wxss`，手工维护与现有格式相符的 WXSS 变量；先仅由试点页显式导入，不接入全局。无需新增生成器或构建链。
2. 建立具名的公共按钮、内容面、标签和表单外观类，例如 `mg-button` 及语义变体；可放在独立、显式导入的样式文件，暂不覆盖旧 `.btn`、`.form-*`。
3. 逐个统一 `section-header`、`avatar-display`、`skeleton-image` 的文字、尺寸和占位。修改共享组件默认外观前列出全部消费者，一次只改一个组件；组件隔离下单独验证 Token 可用性。
4. 稳定后供阶段 1 页面复用并移除对应局部重复定义。相同状态结构在至少两个页面验证后，才考虑提取轻量状态组件；纯样式容器不新增组件。

**允许改动：** 新增样式文件、上述展示组件的外观、明确登记的消费者。**禁止：** 改组件事件契约、删除旧属性、调整 `entry-item` 路由、改 `feedback-modal`／`action-modal` 提交逻辑或安装 UI 库。

**验收标准：** 展示组件覆盖长标题、长姓名、99+计数、无头像、图片失败与小屏；按钮样例覆盖默认、按下、禁用、处理中；组件隔离及全部实际消费者无视觉破坏；未显式接入的页面不受新增样式影响。真实写按钮的防重行为留给业务阶段验证，不因外观完成而宣称已实现。

**回退边界：** 新样式及每个组件分别可回退；保留旧组件属性和调用方式。

## 六、阶段 3：全局 Token 与样式兼容

**目标：** 从局部范式扩展到统一的全局基础，同时控制继承影响。

**执行步骤：**

1. 把已验证的 Token 接入 `app.wxss` 与必要组件；检查 `variables.wxss`、`common.wxss` 重复导入和覆盖顺序。
2. 按实际消费者分组映射旧变量。先处理品牌及中性色，再处理字号／间距，最后处理按钮、表单、标签等旧公共类；每组单独比较截图。JSON 的 `legacyAliases` 只是语义参考，不是可直接导入的样式文件。
3. 检查同名颜色在文字、描边和背景中的不同用途，修正不完整配对。不能把旧线框按钮单换为新蓝后就算主按钮完成。
4. 对已经迁移的页面消除重复硬编码，保留暂未迁移消费者所需的别名。组件仍按微信样式隔离规则处理，不靠全局选择器穿透。

**允许改动：** 全局设计变量、字体基础、相关公共样式及为兼容必须调整的页面局部规则。**禁止：** 同时替换 TabBar 结构、修改安全区算法、重排任务流程、删除仍有消费者的旧变量。不得把装饰分隔色直接用作必要输入边界。

**验收标准：**

- Token 值与规范一致，列出的 20 组对比检查仍满足阈值；实际新增组合另测，透明／图片底按合成结果验证。
- 31 页的可访问默认态与适用角色至少逐页检查一遍，共享按钮检查按下、禁用和加载配色，没有白字白底或低对比输入边界。
- 组件内外语义一致，小屏正文实际不小于 15px；不存在因字号和间距调整而无法触达的操作。
- 本阶段不改变请求数量、action、参数、角色结果和计算口径。

**回退边界：** 按变量组／公共类回退，保留新类的必要定义，避免先回退 Token 后留下失效引用。

## 七、阶段 4：一级页面与导航外壳

**目标：** 统一最容易被感知的产品骨架，再调整业务内容。

**执行步骤：**

1. 统一 `app.json` 的导航背景、文字、页面背景等视觉配置，以及各页相应覆盖；不改路由清单。一级页保留自定义顶部栏，二级页优先原生导航，需切换时逐页处理返回与布局。
2. 调整 `custom-tab-bar/index.*` 为悬浮白底、品牌蓝选中态、图标加文字；按用户 2026-10-25 确认，左右留 64rpx，底边位于安全区上方 16px，使用胶囊圆角与轻阴影。保留角色决定的 3／4 项、选中同步及必要交互锁。
3. 统一窗口、状态栏、胶囊和底部安全区的测量口径；处理 `custom-navbar.wxss`、`.safe-bottom`、`.footer-fixed` 与页面硬编码底部留白。占位按实际栏高＋16px，安全区只算一次。
4. 依次整理首页、维修组首页、我的：首页保留导航下方自动播放的照片 Banner，随后为快捷入口、轻量问候与当前事项；特色活动、团队风采和自动循环的荣誉履带置于事项之后。Banner 与荣誉不设手动暂停入口。其他一级页主行动与当前事项在前，工具／团队内容在后；维修组自然滚动，去除阻止小屏触达的整页裁切。现有数据不足就保留静态入口，不新增聚合查询。
5. 移除首页、报修等整页横滑切 Tab；保留轮播自身手势、值班局部横滚与系统返回。只删除与整页切 Tab 对应的处理，不顺带重写报修表单。
6. 审核 `entry-item` 的全部调用者，统一由父页经 `router` 负责跳转，避免组件自身 `wx.navigateTo` 与父页监听同时跳转。单独提交该行为变更，保证原有 path／事件消费者完成适配。

**允许改动：** TabBar、顶部栏、导航颜色配置、四个一级页布局、整页切 Tab 手势与入口路由绑定。**禁止：** 更改四级角色定义、绕过启动守卫、放宽页面访问、增加假统计、调整报修阶段或业务写 action。

**验收标准：**

- user 看到首页／报修／我的，内部角色增加维修组，顺序与选中态正确；普通用户不能靠直达进入内部页面。
- 每次点击入口只发生一次跳转；普通页面与 Tab 使用正确路由方式；切 Tab、连续点击、返回与身份变化不出现永久锁死。
- iPhone 手势区、Android、320px 小屏与系统大字体下，顶部不撞胶囊，底部内容和操作可达，无重复安全区或大块空白。
- 原生返回、轮播手势与表格局部横滚可用；报修输入不再触发意外切 Tab。

**回退边界：** 导航外观、测量逻辑、入口事件分别保留边界；回退时检查所有 Tab 消费者，不恢复会导致越权的身份处理。

## 八、阶段 5：列表、详情与统计呈现

> 2026-10-25 范围更新：EWA 统计子页及专属 Canvas 图表已按用户要求移除，本文涉及该子页和组件的任务终止；保留排名、编辑、重新汇总与 Excel 导出。历史验证不改写，实际移除见 [EWA统计功能移除与验证](../开发日志/2026-10-25-EWA统计功能移除与验证.md)。

**目标：** 把最多的重复信息页纳入同一语言，仍保留既有业务写流程。

**执行步骤：**

1. 从消息列表、待办列表与报修进度详情开始，统一搜索／筛选区、标题＋状态、时间、人员、详情信息组和分页反馈。
2. 再覆盖维修列表／详情／管理列表、志愿列表／详情／管理列表及个人志愿详情、成员名单／详情的只读区域。管理按钮只做外观适配，不改变授权和提交处理。
3. 按模块收敛状态文字和色彩来源，核对 `activityStatusManager.js`、页面映射及行内样式；只改展示映射，不改变后端枚举或依据时间推算权限。
4. 完善首载、真实空、筛选空、失败、缓存过期、追加失败和记录删除状态；沿用 `page/pageSize/hasMore/loadingMore` 与 `onRefresherRefresh`，不重写缓存框架。
5. 对 `pages/team/ewa/manage/index`、`summary/index` 和 `components/charts/` 只调整呈现：固定三科颜色、清楚标注原始值／加权贡献／单位，补可读文字数据，区分 0、缺失和计算失败。
6. 详情返回列表时保留筛选和滚动位置，刷新受影响条目；后台刷新不抹掉当前内容。消息阅读状态不冒充待办处理状态。

**允许改动：** 上述页面展示、读请求状态组织、状态映射、列表返回上下文和 Canvas 绘制样式。**禁止：** 重写 EWA 公式、改数据源和排序的业务含义、修改参与／任免／移出／导出动作、全量引入 outbox 或另建缓存层。

**验收标准：**

- 每个模块按列表＋详情成对验收；相同任务从个人／内部入口看到一致事实，只呈现各自有权的操作。
- 一条、多页、末页、追加失败重试不重号、不跳页、不重复追加；已删除／无权限有返回去向。
- EWA 样例维修 100、志愿 50、值班 20，展示总分为 72；0 不画异常扇形，缺失不写成 0，图外文字可独立读懂数据。
- 长标题、姓名、费用说明和极端数值不压住操作；05 中 E01、E02、N01 的适用展示场景通过。

**回退边界：** 按模块回退页面与其展示映射；共享图表单独回退，不改变已存在业务数据。

## 九、阶段 6：身份、报修与维修闭环

**目标：** 在统一视觉基础上完善普通用户最关键的连续任务，以及对应成员处理路径。

**执行步骤：**

1. 先复核相关 action 的授权、参数、幂等、结果查询与返回 ID。适配器带 `_requestId` 不能视为服务端已经去重；无法保证幂等的创建动作，在调用端使用现有配置关闭自动重试，设计保留上下文与核实去向。必要后台修复单列，不以页面提示替代。
2. 整理启动／登录注册的加载、错误与字段分组，保持身份恢复和角色来源；成员权限码为可选升级入口，不进入日志或草稿。
3. 报修以“选择问题 → 填写信息 → 核对提交”三个用户阶段组织；分类内部渐进选择。费用与预约始终清楚，返回只清除不再适用字段，型号等字段必填性继续沿用真实规则。
4. 联动分类地图与向导，保证返回携带有效分类且保留适用输入。优先完成当前会话内恢复；跨会话草稿只有确认需要时再单列实现，须按用户隔离、默认 24 小时失效且不保存敏感身份资料。
5. 第一段异步逻辑前锁提交，包含订阅授权；拒绝或部分接受通知不阻断报修。区分成功、明确失败、结果待核实，成功只使用真实记录 ID；无可靠 ID 时可到待办列表，不伪造详情。
6. 整理维修受理、分配、完成、取消与代建表单的核对和错误恢复；提交参数与业务规则保持一致，冲突后显示最新状态。
7. 用现有事件总线／SWR 刷新首页、待办与任务列表；页面卸载退订。验证身份失效、重新进入和角色降级时不会重放旧身份操作。

**允许改动：** 启动／登录、报修／地图、维修相关页面、必要的页面级提交守卫与缓存失效接入。**禁止：** 绕过登录、前端自设 EWA、批量改 `apiAdapter` 默认重试、给所有写操作接 outbox、修改数据库模型或以新流程取消已有必填／费用规则。

**验收标准：**

- 05 中 R01–R04、M01–M02 和 N02 全部适用场景通过；user 报修 → member 处理 → user 查看结果的真实链路完整。
- 连点、订阅拒绝、超时、断网恢复、返回改分类均不无说明丢失输入，不产生重复记录；超时未知时不谎报失败或成功。
- 两成员竞争同一任务按后端结果展示，失败者看到最新受理状态；完成后 EW 不由前端重复计入。
- 首个错误可定位，键盘不挡字段／错误／提交，成功后相关入口数据一致。

**回退边界：** 表单布局、状态处理、缓存接入分开；若已补服务端幂等或权限修复，视觉回退不能将其撤销。缺少可靠核实／去重能力时，该条写流程标阻塞，其他独立视觉项可交付但不能把阶段标为完成。

## 十、阶段 7：内部管理操作与抽屉

**目标：** 统一复杂表单和危险操作的审美与反馈，明确对象、影响与恢复路径。

**执行步骤：**

1. 先统一 `action-modal` 的视觉、长内容滚动、键盘、安全区和提交中关闭规则，逐消费者检查；`feedback-modal` 只对齐外观，保留已读与订阅语义。
2. 依次处理志愿创建／编辑／成员选择，再处理 EWA 管理调整／汇总更新／导出，最后处理成员资料编辑、任免与移出。每个子模块分别验收，不把三类操作装进一个大提交。
3. 志愿页面区分活动状态与个人参与状态；仅负责人导入成员时，不添加“立即报名”。修改参与者与工作量影响按真实后端规则解释。
4. EWA 修改先显示原值、新值、对象和所需原因；沿用上限与权限，成功后重读后端，导出失败保留条件，不在前端重新结算。
5. 成员管理按服务端 `permissions` 展示操作，保留版本校验、部门切换冷却、移出原因及交接阻塞。移出确认明确普通账号、历史业务与工作量仍保留。
6. 所有编辑失败保留字段；版本冲突展示变化并要求重新核对，不能静默覆盖。提交中防重、防误关闭，危险动作使用具体文案。

**允许改动：** 上述模块的前端表单、管理反馈、公共弹窗／抽屉及必要缓存失效。**禁止：** 添加／恢复账号或候选人搜索、扩大管理范围、取消交接校验、自动清空任务、变更结算公式或擅自支持自助报名。

**验收标准：** 05 中 V01、E01–E02、U01–U04 通过；组长、管理员、本人和不同目标角色的操作边界与服务端一致；版本冲突／冷却显示真实原因，交接阻塞仍能保留输入并前往处理；取消确认不改变数据，重复点击不重复执行。成员移出使用专用测试对象，确认账号、历史和工作量保留，旧权限不会恢复。

**回退边界：** 弹窗外观与业务处理分别可回退；已完成的移出、任免和工作量调整不能靠前端回退逆转，不能为截图测试触发真实不可恢复操作。

## 十一、阶段 8：值班调度与并发交互

**目标：** 最后改造状态最密集、时效最强的操作界面，沿用已经稳定的列表、表单与确认方式。

**执行步骤：**

1. 先做 `pages/team/duty/roster/index` 的周次＋日期范围、编辑状态、时间列和局部横滚；提供个人已选文字列表，不依赖颜色或单元格位置理解状态。
2. 显式区分可选、预选、已确认、他人占用、锁定和冷却；点击第 4 段解释上限并保留有效选择，计数口径与服务端一致。

**允许改动：** 值班两页的布局、状态呈现、前端选择／核对和冲突恢复。**禁止：** 改配额、锁时长、冷却、周次规则、确认后撤销限制，将时效写操作放入 outbox 自动重放，或以纯前端判断替代后端锁。

**验收标准：** 05 中 D01–D03 全部通过；两个真实客户端的冲突结果与最终记录一致；跨周不误写，锁与确认不混淆，冷却时间只引用后端值；小屏表格可局部横滚，页面其余内容不横滑切 Tab，文字列表可独立核对；管理操作取消后数据不变。

**回退边界：** 先回退显示与选择层，保留并发保护和后端状态；已确认排班不随代码回退被自动撤销。并发保障不足时记录独立后台修复项，不带缺口进入发布验收。
