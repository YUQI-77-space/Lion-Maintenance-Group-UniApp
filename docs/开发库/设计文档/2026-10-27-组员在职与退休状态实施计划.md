# 组员在职与退休状态实施计划

创建日期：2026-10-27。用户已确认：退休仅保留历史只读能力，停止新增业务和管理操作；有未完成负责事项或未来排班时不得退休，先人工沟通推进现有任务，不新增交接流程。

## 数据与接口

- 角色与在职状态独立，使用 `employmentStatus=active/retired`，缺失字段视为在职。`users` 为身份来源，`proUsers` 同步此字段作为投影；原有用户、投影、业务、待办、EWA 和审计记录全部保留。
- 新增 `changeMemberEmploymentStatus`，同一事务更新状态、版本和审计；退休前沿用现有未完成维修、未来或异常值班、未结束志愿活动检查。恢复在职不恢复旧快照、不改角色、不重算 EWA。
- 禁用旧 `removeTeamMember`，不再有降为 `user` 或删除成员投影的路径。角色调整只接受 member 与 leader 的互换，管理员角色不在这里调整。
- 管理名单新增在职／退休／全部筛选，默认在职；当前状态与版本均由后端返回。

## 权限与展示

- 退休身份仍保留原角色和历史读取；各业务写入口服务端拒绝退休调用者，新增任务受理人、志愿导入和排班也拒绝退休目标。组员管理和 EWA 不向退休身份开放。
- 维修任务、志愿活动、值班、待办等人员展示通过当前身份补充状态，仅在响应中标注，不回写历史姓名或任务快照。统一使用中性“已退休”文字标签，不只依靠颜色。
- EWA 排行、管理目标、批量汇总和导出均只选当前在职成员；退休人的历史汇总和手动调整保留，历史结算不因标签切换被重置。
- 管理页将“移出维修组”替换为“编辑在职状态”，使用原生 picker 和普通保存确认，保留提交锁、失败输入、版本和幂等保护。顶部筛选允许换行，遵守 48px 点击热区与现有设计 Token。

## 实施与验证顺序

1. 先改成员域、登录投影与状态接口，再改权限边界、关联响应和 EWA 人员口径，最后接入页面状态编辑、筛选及标签。
2. L0 核对调用链、数据和部署单元；L1 验证状态双向切换、角色不变、阻塞事项、数据保留和列表筛选；L2 覆盖登录、业务写保护、退休目标过滤、历史标签、EWA 排名与导出、前端失败和版本冲突。
3. 对 WXML/WXSS 使用现有微信编译工具做受影响文件编译；不机械重跑全项目或长测。真实微信身份、真机布局和生产写入验收单独注明。
4. 上线前只读核对旧移出身份；当前调查时旧移出数量为 0，不需要批量迁移成员。部署前备份受影响云函数，生产不以真实成员试验退休与恢复。

旧移出方案与调查记录作为历史证据保留；更新当前业务说明和相关设计规范，最终实际改动、验证和未覆盖项另记开发日志。
