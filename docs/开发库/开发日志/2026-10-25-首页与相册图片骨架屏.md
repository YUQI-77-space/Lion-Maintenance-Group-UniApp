# 首页与相册图片骨架屏

创建日期：2026-10-25。范围：首页特色活动、团队风采、团队荣誉，以及特色活动／团队风采完整相册。代码已实现，本地逻辑与静态编译已验证；原生与真机待验收。

## 实际修改

- 复用 `skeleton-image`，图片请求期间保留原尺寸的中性骨架；成功后自行展示，失败或地址为空时显示“图片暂不可用”。不等待同组其他图片，不增加定时延迟或持续闪烁动画。
- 图片地址变更时复位加载状态，相同地址的父页更新不复位；保留 `imageloadcomplete` 的尺寸／错误信息，以及旧 `showImage` 方法兼容。
- 首页接入特色活动大图和两张小图、团队风采横滑、荣誉履带双组图片。荣誉第一组继续把完成事件分发给原有尺寸计算与失败重载逻辑；副本独立展示，不重复触发父页处理。轮播、跳转、图片来源与权限不变。
- 首页仅在真实加载中且列表为空时展示整组骨架；空列表加载结束后显示相应空态。占位使用 `bg-subtle` Token，团队风采占位沿用横向排列，荣誉整组占位不播放履带动画。
- 两个完整相册首帧及首次请求使用同布局卡片占位，追加请求在原有照片之后展示两张占位卡；单图继续占位直到图片实际完成。移除父页逐张选择组件放行的重复调用。
- 相册请求未结束时，重复下拉不清空现有内容或重置页码，避免在途分页结果与刷新状态混淆。每页 12 张、URL 转换失败回退原地址、图片失败刷新提示均保留。
- 更新两份既有图片测试以验证自动展示合同，新增 `tests/image-skeleton.test.js` 覆盖换源、同源更新、失败恢复、慢加载防重、末页、空数据与转换失败回退。

## 设计依据

遵守[视觉规范](../../知识库/Design/01-设计语言与视觉规范.md)的图片占位、语义色与克制动效要求，以及[组件规范](../../知识库/Design/02-组件规范.md)的固定图片比例、失败结束骨架、加载与空态区分要求。属于现有前端计划阶段 1／2／4／5 的局部补充，不改变其他阶段验收状态。

已读取 ponytail、项目 ui-ux-pro-max，并检索 `skeleton loading image layout` 的通用 UX 指引；仅采纳预留媒体尺寸、防止异步内容引发布局跳动的建议，不引入 Web 框架或依赖。
