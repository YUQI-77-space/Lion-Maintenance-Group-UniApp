## 数据保护与兼容策略

- 保留 5 分钟预选锁和每周最多 3 段（含已预选、已确认）的配额。空闲时段可直接正式确认；他人占用和有效锁不能覆盖；非法锁信息按失败处理，不猜测归属。
- 事务只使用当前 SDK 支持的文档 API。需要查询时先发现文档 ID，再在事务中重读真实值；确认路径重读当前周记录，并与配置写入形成竞争边界。配置／排班／权限发生冲突时返回失败，调用方刷新核对，不自动盲重试。
- 全局配置文档承担选择串行化，适用于当前通常每周 35 段的小规模排班；并发高时可能增加冲突，需要刷新重试。这是保守的数据保护选择，没有承诺所有并发请求都会成功。
- 新待办采用固定 ID 防重复，旧随机 ID 待办继续原位使用；归属或重复数据异常时拒绝覆盖。已确认请求重放保留已有待办和状态。
- 历史 `ended` 记录按已经处理保留，不自动补发或回退；异常工作量与重复汇总拒绝自动覆盖。保留历史不等于历史错误账目已经修复。历史漏记、提前结算或错误总分需要另行只读审计、备份及受控修复。
- 本轮未执行全员汇总或历史重算；未将本地测试结果当作云端数据修复证据。
