# TabBar 选中态闪动修复

日期：2026-10-24。

## 问题与已实现

用户要求点击导航时，旧按钮与目标按钮同时切换样式，其余按钮、尺寸和背景保持稳定。

源码发现：组件初始 `selected: 0`，先提交导航列表再纠正选中项，存在首页误亮的中间状态；每个页面独立持有 TabBar，旧实例在跳转完成后仍按栈顶路由更新；图片切换依赖替换 `src`；原生 hover 残留浅蓝背景，选中时加粗文字。

- `custom-tab-bar/index.js`：未确定所属页时不默认选中首页；列表与选中项同次 `setData` 提交；按所属页面路由更新，隐藏实例不猜测栈顶路由。点击先提交选中态，渲染回调再导航；成功只释放防重锁，失败恢复所属页选中态并提示。
- 四个一级页面在 `onShow` 显式提供 `this.route`。保留 `setSelectedByRoute()`、`forceRefresh()` 与交互锁接口。
- `custom-tab-bar/index.wxml`、`index.wxss`：普通／选中图标同时挂载，使用透明度同步切换；固定图标尺寸，不再更换图片地址；关闭额外 hover 背景，选中态只变品牌色，不改变字重。
- 新增 `tests/tabbar.test.js`，覆盖三个／四个入口的全部切换组合、初始化、旧实例刷新、返回、角色变化、解绑、防重、交互锁与失败恢复。

设计依据为知识库 Design 的 01、02、04、06 与 `design-tokens.json`，沿用品牌蓝、56px 内容高度及安全区。按用户本次要求使用即时选中反馈，未增加选择动画或其他区域的反馈。UI Skill 的 `navigation state flicker` 检索中采用通用 Navigation / Active State 建议，未采用 Web 路由示例。
