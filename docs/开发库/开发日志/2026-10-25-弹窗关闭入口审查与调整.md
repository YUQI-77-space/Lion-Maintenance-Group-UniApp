# 弹窗关闭入口审查与调整

创建日期：2026-10-25。对应前端设计改造阶段 5／9 的弹窗交互补充。

## 审查范围与结论

检索全部 39 个 WXML 文件（当前注册页面 30 个），去除注释后核对关闭、取消、完成、知道了及 close／hide／cancel 等候选入口，并检查相关处理函数和公共弹窗组件。

| 候选 | 结论与处理 |
| --- | --- |
| 消息详情底部“关闭” | 仅收起详情，改为右上角叉号，移除底部整行按钮及其样式 |
| 待办撤销、志愿反馈、按人 EW 等弹窗“取消” | 与撤销／提交／保存组成业务决策，保留；部分头部已有叉号 |
| action-modal 的取消／返回修改 | 编辑、保存和成员移出流程使用；保留文案与提交中禁止取消的守卫 |
| feedback-modal 的“确认收到” | 会标记反馈已读，并可能触发志愿邀请订阅授权和提醒调度，保留 |
| 值班设置、重置、删除等确认层 | 与确认操作成对，属于业务决策，保留 |
| 微信原生 showModal 的“知道了／我知道了” | 沿用平台外观；未为替换按钮重写原生弹窗 |
| 页面返回、取消报名、关闭招募等 | 属于导航或业务状态操作，不替换为叉号 |

在本次源码范围内，符合“纯展示弹窗底部仅关闭”条件的有效入口为消息详情一处。没有批量修改含取消字样的操作。

## 实际改动与规范

消息详情使用明确宽高的 48px 原生迷你按钮，显示 `×`，标注“关闭消息详情”读屏名称，保留按下反馈和原关闭处理函数；标题右侧预留按钮空间。删除底部容器及无用样式，同步更新处理函数注释。

将纯展示弹窗优先使用右上角叉号、业务确认保留明确动作名称的规则补入 [组件规范](../../知识库/Design/02-组件规范.md)。未改变接口、权限、消息已读或提交逻辑。
