# 维修任务票根认领交互

创建日期：2026-10-28。依据：[组件规范 · 卡片与列表](../../知识库/Design/02-组件规范.md#4-卡片列表与功能入口)、[设计语言 · 动效](../../知识库/Design/01-设计语言与视觉规范.md#7-动效)。状态：本地实现完成，未提交、未上传、未做真机验收。

## 问题

维修任务列表的「认领」是挂在卡片内容下方的独立按钮行：`.task-footer` 在 `.task-info` 内部再撑出一行高度，按钮与卡片主内容之间只有 `padding-top: 12rpx`，视觉上像一张卡片里塞了两个东西；「待受理」与「已受理」的差别也只能靠状态标签文字辨认。

## 方案

把认领做成电影票的撕票动作，票根就是按钮。

| 结构 | 作用 |
| --- | --- |
| `.task-card`（去内边距）→ `.task-info`（自带 20rpx 内边距）＋ `.ticket-stub` | 票根纵向与卡片等高，不再额外占一行；卡片 `overflow: hidden` 让上下缺口被裁成半圆 |
| `.ticket-stub` 96rpx 宽、上下边缘各一个页面底色半圆、`border-left: 2rpx dashed` | 48px 热区达标；虚线＋缺口构成票根语汇 |
| `.stub-paper` 内竖排「认领」（两个 `<text>` 独立成行） | 不依赖 `writing-mode`；品牌蓝 13px |
| `.stub-tear`（默认 `display: none`）＋ `.stub-tear::after` 锯齿 | 撕拉蒙层：页面底色自顶部向下生长，下沿是同底色锯齿（SVG 数据 URI，`--mg-color-bg-subtle` = `#EEF1F5`）＋ 2rpx `drop-shadow` 毛边 |
| `.stub-ghost` | 撕痕：页面底色 ＋ 左侧虚线 ＋ 内阴影，55% 后渐显；「进行中」卡片静态显示 |

时序：连续点击 → 既有确认弹窗 → 订阅授权 → 校验最新状态 → `assignMaintenanceTask`，成功后

1. `tornTaskIds[taskId] = true` 触发 900ms 撕拉（纸面淡出 900ms / 标签 520ms / 蒙层 900ms `cubic-bezier(0.45,0.05,0.55,0.95)` / 撕痕 900ms）；
2. 等待 900ms 后 `loadMaintenanceTasks(true)`，避免刷新重排打断动画；
3. 刷新完成后清理 `tornTaskIds`，任务以服务端状态渲染（`inProgress` → 静态撕痕）。

设计取舍：

- **动画不参与状态判定**：受理是否成立只看服务端返回与刷新结果，`TICKET_TEAR_MS` 只控制刷新时机（依据 Skill 提示 “不要用 animationend 决定状态正确性”）。动画被系统打断时，卡片仍会在刷新后落到正确状态。
- 票根仅在 `!readOnly && taskStatus === 'pending'` 渲染；已退休、已完成、已取消回到全宽卡片，避免无意义占位。
- `prefers-reduced-motion: reduce` 下跳过过程直接呈现撕痕。
- 撕拉蒙层用 `height` 增长而非 `scaleY`：`scaleY` 会把毛边锯齿一起压扁，锯齿在窄条上才是“毛边”。代价是每条只重排一个绝对定位窄条，不影响卡片内文字布局。
- 锯齿颜色写死在数据 URI 里（`#EEF1F5`），与 `--mg-color-bg-subtle` 一致，已在注释标注同步要求。

## 修正：撕口处的描边

真机截图反馈：撕口半圆看起来是“贴进去的一枚浅色圆点”，卡片描边从缺口上方平直划过，票根不真实。原因是卡片 `overflow: hidden` 把子元素裁到 padding box，半圆只能落在描边内侧，描边本身仍完整绘制。

改法：

- 卡片去掉 `overflow: hidden`；票根底色改为透明（白色底交回卡片本身）并给票根 `border-radius: 0 10rpx 10rpx 0`，让自身按下态与圆角对齐，同时不再需要裁剪子元素。
- 撕口半圆圆心压在卡片描边上（`top/bottom: -12rpx`）：上半落在卡外与页面底色同色，下半在卡内形成缺口，**描边在缺口处被“咬断”**。
- 失去卡片裁剪后，锯齿会垂到卡外，因此把 `overflow: hidden` 移到撕拉蒙层自身，并把蒙层底色换成 `linear-gradient`（最后 18rpx 透明），锯齿三角留在蒙层内、纸面从齿缝透出，仍是毛边而不是贴一条锯齿带。

## 验证

- `node tests/ticket-tear.test.js`：5 项通过——成功先撕后刷新、900ms 与 WXSS 对齐、动画期间不刷新、失败不播撕拉直接刷新、自身报修与二次点击拦截、不可写状态不触发、结构与样式契约。
- `node tests/*.test.js`：15 个文件全部通过。
- 用 Chrome 无头浏览器把 WXML/WXSS 按 1rpx＝0.5px 还原为 HTML 做静态观感校对（票根完整 / 撕到 42% / 撕完 / 进行中四种状态，4x 放大检查描边被撕口咬断、锯齿毛边、虚影），修正描边问题后再次复检。这只用于检查 CSS 表现，**不是**小程序真机或开发者工具验收。

## 未覆盖

- 未在微信开发者工具或真机验证：iOS/Android WebView 对 `drop-shadow`、`prefers-reduced-motion` 与内联 SVG 背景的实际支持与性能；长列表连续撕拉时的合成层开销。
- 未处理“撕到一半切后台/页面隐藏”的表现：动画会随页面冻结，回到前台继续；未额外做暂停恢复。
- 未做深色模式适配（项目当前无深色主题）。
