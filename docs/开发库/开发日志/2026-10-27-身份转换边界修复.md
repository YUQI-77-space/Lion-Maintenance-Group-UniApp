# 身份转换边界修复

创建日期：2026-10-27。

对应 [组员组长身份转换业务审查](../审查文档/2026-10-27-组员组长身份转换业务审查.md)。本次在已有未提交改动上增量修复，未回退工作区、未修改生产数据、未提交 Git、未部署。

## 1. 实现结果

| 问题 | 已实现行为 |
| --- | --- |
| R1 值班接口漏鉴权 | 清空、生成和强制释放锁复用基于 users 的在职 leader/admin 校验；拒绝重复身份、退休和缺失身份，forceDelete 无法跳过 |
| R2 任务通用更新越界 | 真实调用方仅设置 EW，因此保留原 action 并收窄为单一数值 EW 字段；拒绝状态、受理关系、任意注入及无效数值；在事务内复查当前管理角色 |
| R3 最后管理者退出 | 降权和退休前保留至少一名可鉴权的在职管理者；重复 openid 和退休身份不计入兜底；事务共写剩余管理者身份，防止两人并发退出 |
| R4 在途请求旧授权 | 维修代分配、代建、受理人增删和 EW 设置在业务事务中重读管理角色；活动创建、导入也补上同类保护；组员不能批量导入其他志愿者 |
| R5 身份和页面不同步 | 独立身份事件；当前页面接收身份更新钩子，失去权限的管理页退出；统一处理 API 权限拒绝；拒绝晚到旧版本／其他账号响应；本人成功降权先应用返回身份 |

同时移除完成任务对旧 proUsers 组长身份的回退，维修管理成员查询、任务列表和受理人操作以 users 为身份权威。统一所涉及维修、志愿、值班、EWA 和消息接口的管理员继承判断，以及相关前端管理入口／操作条件，避免只剩管理员时无法直接处理业务。

角色调整保留双集合、原成员 ID、部门、任务、值班、报名和历史工作量。没有加入新的数据库集合、身份迁移、前端框架或依赖。最后管理者保护复用 users 文档的并发写冲突，不要求预先创建全局锁。

## 2. 主要位置

- 身份事务和接任保护：[memberManagement.js](../../../cloudfunctions/users/memberManagement.js)。
- 值班鉴权：[switchToWeek.js](../../../cloudfunctions/dutySchedule/switchToWeek.js)、清空／生成／强制解锁 action。
- EW 字段边界：[updateMaintenanceTasks.js](../../../cloudfunctions/maintenanceTasks/updateMaintenanceTasks.js)。
- 维修及活动事务：各业务 action，继续复用各独立部署单元现有的 memberStatus 事务工具。
- 客户端身份通知和版本防护：[identity.js](../../../miniprogram/utils/identity.js)、[app.js](../../../miniprogram/app.js)、[apiAdapter.js](../../../miniprogram/utils/apiAdapter.js)。
- 成员本人操作成功后应用返回身份：[page.js](../../../miniprogram/pages/team/members/page.js)。

前端遵循设计规范 04 的“运行中权限拒绝刷新身份、真实成功结果更新界面”合同，只修改状态和权限行为。ui-ux-pro-max 的两次定向检索未找到适合此身份时序问题的专门建议，因此以项目规范和原生页面生命周期为依据，没有采纳网页导航、字体、配色或触觉反馈示例。

## 4. 部署与尚未验证

本次修改的云函数部署单元是 users、dutySchedule、maintenanceTasks、volunteerActivities、equivalentWorkloadAssessment、messages；前端新增 utils/identity.js 并更新调用方。应先部署后端保护，再发布前端；工作区中本次之前已有的其他改动仍需遵守各自部署说明。

尚未部署，也没有核对线上是否正在运行相同代码；没有执行微信开发者工具编译、真机页面交互、真实账号切换和真实 CloudBase 并发冲突验收。源码解析与内存／SDK 边界验证不能替代这些步骤。多管理者事务写冲突、真实客户端身份时序应在隔离测试环境验收，避免用真实成员试验降权。

前台持续停留且没有请求时，没有新增实时数据库订阅或轮询，不承诺立即感知另一设备的调整；一旦从后台返回或服务端返回 401／403，会刷新并收敛客户端身份。服务端权限仍以当前 users 身份为准。
