# 列表卡片入场动画恢复

创建日期：2026-10-28。依据：[设计规范 · 动效](../../知识库/Design/01-设计语言与视觉规范.md#7-动效)。状态：本地实现完成，未提交、未上传、未做真机验收。

## 背景

用户此前设计的「列表卡片依次滑入」在 `14bbcd3`（2026-10-25「优化：统一公共样式与加载搜索组件」）中，`styles/data-pages.wxss` 给 `.mg-data-page` 下的 `task-card`／`activity-card`／`card` 加了 `opacity: 1; animation: none; transform: none`。当时的真实问题是**基础卡片类依赖 `opacity: 0` + 动画结束恢复可见，而志愿活动两个页面在加载成功路径上没有下发 `card-animate`**，导致卡片永久透明（见 [列表卡片首次进入不可见修复](../开发日志/2026-10-24-列表卡片首次进入不可见修复.md)）。本轮恢复动画时不重复该前提。

## 实现

| 位置 | 改动 |
| --- | --- |
| `styles/data-pages.wxss` | 以 `@keyframes mg-card-enter` 取代「禁用动画」规则；`.mg-data-page .X.card-animate` 统一 `650ms cubic-bezier(0.16, 1, 0.3, 1) backwards`；新增 `prefers-reduced-motion: reduce` 关闭入场 |
| `pages/team/maintenance/list`、`.../maintenance/manage`、`.../volunteer/list`、`.../volunteer/manage`、`pages/user/todo` 的 WXSS | 删除各自重复的 `.card-animate` 动画与 `@keyframes cardSlideIn`，删除基础卡片类的 `opacity: 0` / `translateX(80rpx)`；保留 `:active` 按压反馈 |
| 五个列表页的 JS | 用 `buildCardDelays(startIndex, total)` 生成延迟，并与卡片列表**在同一次 `setData`** 下发；删除两段式的 `triggerCardAnimation` |
| `pages/team/volunteer/list`、`.../volunteer/manage` 的 JS | 补齐此前缺失的入场触发：`getActivitiesList` 成功分支随列表一起写入延迟，首屏从 0、分页追加从旧列表长度开始；筛选缓存直出也在同一 `nextState` 里带延迟 |
| `pages/team/maintenance/manage` 的 JS | `filterTasksByStatus(status, animateFrom)` 增加起始下标参数，加载更多只让新卡片入场；搜索与清空搜索同样同批下发延迟 |
| `tests/list-card-visibility.test.js` | 契约改为：基础卡片态可见（不得为 `opacity: 0`、不承载 animation）、带 `card-animate` 时引用 `mg-card-enter` 且为 `backwards`、存在减少动效兜底 |
| `tests/list-card-entry.test.js` | 新增行为契约测试：承载列表的那次 `setData` 必须同时包含延迟，且列表写入之后不得再单独补延迟 |

关键设计取舍：

- 归零了旧的「基础类隐藏」前提。旧实现靠基础类 `opacity: 0` + 动画 `forwards` 补可见，一旦动画类缺失、被打断或延迟下发的 `setData` 未执行，卡片永久隐形。现在基础类本身可见，隐藏只发生在动画延迟期间（`backwards` 使用 0% 帧），动画结束回到基础态，`:active` 按压位移也不再被 `forwards` 覆盖。
- 动画与曲线集中到公共样式，五个页面只保留 `cardDelays` 数据与 `card-animate` 类名，避免五份 `cardSlideIn` 各自漂移（旧实现中待办页为 0.5s／60rpx，其余为 0.6s／80rpx）。
- 快入缓出取 `cubic-bezier(0.16, 1, 0.3, 1)`：起步位移快、末段收敛慢。
- 逐条延后由各页 `triggerCardAnimation` 下发：2026-10-28 实机观感反馈“速度偏高、间隔过小”后，单卡时长由 420ms 调到 650ms，步长由 100ms 调到 180ms。
- 志愿活动两个页面此前从未调用入场触发（仅搜索确认与缓存切换时调用），因此仅恢复 CSS 不会出现动画；本轮补齐了加载完成链路。
- 入场延迟必须与列表数据**同一次 `setData`**：先渲染终态列表、再补 `card-animate` 会让卡片先以终态出现一帧，随即被拉回入场起点，表现为“列表闪一下再消失重播”。`buildCardDelays` 返回对象随列表一并下发，卡片节点在创建时就带着 `card-animate` 与 `animation-delay`，只可能从 0% 帧开始。
