# EWA 排名与统计界面二次重构

创建日期：2026-10-25。范围：`pages/team/ewa/manage`、`pages/team/ewa/summary`、两页共用的 EWA 外观层，以及 `components/section-header` 的可选扩展。本文记录本轮实际改动与验证结果；业务接口、权限与数据口径未变化。

## 一、背景与目标

用户认为第一次重做后的排名页与统计页视觉质量仍不达标，要求按项目设计规范与大厂审美整体重做，并且不能为这两个页面另起一套视觉：能复用的组件必须复用，设计值只走统一 Token 文件。

本轮目标：

1. 用同一套语义 Token 与公共外观类重写两个页面，删除页面内自造的颜色、字号与容器。
2. 降低页面噪声：合并重复标题、单位与说明，收敛卡片层级与分隔线，让数据优先于装饰。
3. 复用已有组件而不是再造：`section-header`、`avatar-display`、`loading-animation`、`action-modal`。
4. 保留全部业务行为：分页、检索与防抖、缓存、导出、更新汇总、工作量调整，以及接口参数与重试策略。

## 四、关键取舍

| 决策 | 理由与边界 |
| --- | --- |
| 导出 / 更新汇总移到页尾“数据管理” | 两者是低频管理动作而非浏览主任务；移出首屏后列表提前约 120px 出现。每行补一句用途说明，避免“更新汇总”含义不明。更新成功后回到页首查看新数据。 |
| 整行点击进入调整，行尾使用箭头 | 取消每行重复的“调整”按钮，行高从约 120px 降到 68px，一屏可读约 9 位成员；说明区保留“点击成员可调整工作量”，箭头本身不承担唯一线索。 |
| 三科数值用“维修 5 · 志愿 0 · 值班 0”单行展示 | 名次、姓名、总分、三科原值一屏可读；320px 下通过媒体查询压缩行内留白，保持单行不折行。 |
| 统计页用单条堆叠构成条替代三条独立进度条 | 同一条形同时表达三科占比，颜色与下方文字列表一一对应；0 与缺失时不画占比并给出原因说明。 |
| 排序说明与上限移到底部说明 | 首屏只保留一行公式；单位在区块标题右侧声明（单位：分 / 单位：EW），避免每个数值重复后缀。 |
| 复用 `action-modal` 承载调整抽屉 | 复用既有的遮罩、键盘高度、安全区与提交锁表现，删除自造抽屉的 60 余行样式与重复关闭逻辑；抽屉内容仍为页面样式，符合 `slot` 的样式作用域。 |

## 五、接口、权限与数据影响

- 未改动任何 action 名称、参数结构或云函数：排名仍调用 `equivalentWorkloadAssessment.getRanking`（`page/pageSize/sortField/sortOrder/includeUserRanking/search`），导出、更新汇总与调整仍为 `exportExcel`、`updateSummary`、`updateUserEW`。
- 两个写操作保持原有 `config: { retries: 0 }` 与提交锁；调整仍先经系统确认弹窗核对原值 → 新值，再由服务端结算总分。
- 权限边界不变：排名页仍仅 `leader`，统计页仍为 `member+`，由 `router.checkPermission` 与服务端共同决定。
- 展示口径不变：总分取服务端 `totalEW`，缺失显示“—”，真实 0 显示 0；占比以三科加权贡献合计为分母。

| 目视检查（375） | 排名正常 / 展开 / 搜索命中 / 搜索为空 / 失败 / 空数据 / 调整抽屉；统计正常 / 缺失 / 零值 / 空数据 | 层次、状态与空态可读；长姓名换行不挤压分数；列表末尾显示“已显示全部成员” |

源码映射把 WXML/WXSS 转成浏览器布局并注入脱敏样例，只能说明布局与尺寸，**不等同于微信原生渲染或业务接口验收**。预览脚本、截图与结果保存在 `项目管理/设计验收/2026-10-24-EWA界面重构/`（已确认被 Git 忽略）。
