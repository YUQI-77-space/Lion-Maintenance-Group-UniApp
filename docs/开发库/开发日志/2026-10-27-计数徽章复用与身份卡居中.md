# 计数徽章复用与身份卡居中

日期：2026-10-27。

## 实际改动与复用方式

按用户追加要求，将个人页顶部改为头像、姓名、身份自上而下三行排列，整体沿卡片中轴水平居中。卡片最小高度由前一版 280rpx 增至 480rpx，长内容自然撑高；头像使用已有 `avatar-display` 的 xlarge 200rpx，姓名使用 section 16px、身份使用 caption 12px。退出按钮仍为右上角图标，保留 48px 热区、无障碍名称、确认与既有退出处理。

新增原生展示组件 `miniprogram/components/count-badge/`，个人页“待办事项”和“消息”都已实际使用该组件，移除页面两套徽章样式。

- `count`：Number，默认 0，调用方提供非负整数；0 隐藏、1–99 原数显示、超过 99 显示 `99+`。
- `label`：String，默认“待处理事项”，页面分别传入“待办事项”和“未读消息”；读屏名称保留完整数值。
- 鲜红实底白字、28px 圆形，样式与显示规则在组件内统一维护；虚拟宿主使零值隐藏时不留下空占位或额外 flex 间距。
- 组件只读展示，数量获取、刷新与导航仍由原页面负责，没有云请求、写入或点击处理。

其他页面在 JSON 注册 `"count-badge": "/components/count-badge/index"` 后即可使用：

```xml
<count-badge count="{{todoCount}}" label="待办事项" />
<count-badge count="{{unreadMessageCount}}" label="未读消息" />
```

将上一版页面局部红色提升为统一 `--mg-color-notification: #DC2626` Token，同步权威 JSON、WXSS 和设计规范 01／02／03；Token 版本更新为 1.3.1，既有 Token 数值保持原样。只新增该语义变量，不修改已有组件默认样式。没有修改个人页 JS、权限、接口、请求次数、缓存或数据写入路径。

## 设计依据

遵守设计规范 01 的中文字号、留白、点击热区，02 的只读展示职责与组件隔离要求，03 的个人身份卡主导层级。按用户明确的复用要求新增组件，当前两个实际使用位置均在个人页。

`ui-ux-pro-max` 查询 `badge count screen reader --domain ux` 命中 Web 平台上下文计数播报建议；仅采用“名称＋完整数量”的通用语义，在小程序使用现有支持的 `aria-label`，未引入 Web live region 或外部依赖。

## 渐进验证

L0：确认数量继续来自个人页既有 data／全局刷新回调，徽章不参与业务请求，实际消费者为当前个人页的两个入口。

L1：

- 官方 `wcc.exe` 编译个人页与新组件两个 WXML，`wcsc.exe` 编译个人页、新组件及三个导入样式，退出码均为 0。
- `node --test --test-name-pattern='显式 Token|全部规定色彩组合' tests/design-phase2.test.js`：2 项通过，覆盖新增 Token 的 JSON／WXSS 一致性和全部规定色彩对比度；通知红与白字对比度为 4.829:1。
- 新增组件 `node --check`、两份 JSON 解析、页面注册路径的四个组件文件引用检查及 `git diff --check` 均通过。

L1 通过后，因新增共享展示组件进入 L2，覆盖其两个实际使用位置：

- 复用既有源码映射预检入口，320／375／430px 各覆盖短姓名、长姓名、零值、1、99、100，共 18 组修改后场景通过；另保留 375px 同数据的修改前截图。
- 检查两处徽章数量、显示规则、圆形、鲜红色与完整无障碍名称；零值时两处均无残留徽章，箭头位置与无计数行一致。
- 检查头像、姓名、身份沿同一中轴排列且垂直顺序正确，卡片高度至少为入口行的 2.4 倍，退出热区至少 48px，头像不与退出按钮相交，页面无横向溢出。

迁移映射脚本时，先后修正了旧版注释定位和原脚本剥离 `aria-label` 的映射问题；这两项失败发生在预检适配层，未改动产品源码或删除断言来获得通过。

源码快照、官方编译产物与日志、前后映射截图、映射脚本及 `layout-results.json` 位于 Git 忽略的 `项目管理/设计验收/2026-10-27-徽章复用与身份卡居中/`。映射头像为脱敏占位；浏览器布局预检不能证明微信虚拟宿主、跨组件点击冒泡或读屏行为已经原生验收。
