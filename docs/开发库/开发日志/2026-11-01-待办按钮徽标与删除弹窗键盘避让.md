# 待办按钮徽标与删除弹窗键盘避让

## 实际问题与修改

待办卡片操作按钮受到公共最小 48px 触控高度约束，但局部样式没有垂直居中，短文字下方形成类似多出一行的留白。现在局部使用 flex 双向居中、等宽按钮、8px 间距和 13px 标签字体，压缩外层 padding，保留 48px 点击高度，不修改公共样式及撤销／完成事件。

侧栏徽标此前位于文字下一行，且白字变量未正确生效。现在分类文字外增加相对定位容器，将徽标绝对定位在右上角；通常为 20px 圆形，99+ 为 24px 圆形，红底白字，零值隐藏，读屏名称保留完整数量。此为用户要求的局部紧凑徽标例外，不修改公共 `count-badge`。

维修任务删除确认弹窗此前按整屏 50% 定位，没有响应键盘高度。现在外层固定覆盖可用区域，通过输入框 `bindfocus`／`bindkeyboardheightchange` 更新底部 px 偏移，在键盘上方居中；关闭原生 `adjust-position`，避免两套位移叠加。关闭或页面隐藏时重置高度，关闭／提交时收起键盘，关闭后和销毁后的迟到事件不再更新高度。保留任务编号严格匹配和后端权限校验；点击外层关闭、点击弹窗内容不冒泡。

采用项目 UI/UX Skill、Design 01／02／06 和现有 Token。定向检索提供移动键盘与焦点不被遮挡的通用建议，实现仍使用微信输入框能力。

## 实际验证

范围为 L1，两处页面局部修改，没有修改公共样式、组件、接口或数据结构，未升级至全量回归。

- `node --test tests/delete-modal-keyboard.test.js`：3 项通过，约 156ms。覆盖键盘高度切换／收起、关闭／销毁后迟到事件、隐藏清理及错误任务编号不得删除。
- 将实际 WXSS 展开并按屏宽换算 rpx，在 Chrome headless 中检查局部布局。320／375／430px 宽，700px 参考视口高度下，280／360px 模拟键盘共 6 种弹窗几何均通过：输入框、页脚均在模拟键盘上方。
- 待办布局初次检查发现 320px 下徽标越界约 2px，收回右侧偏移后，仅复查受影响的 320／375／430px 待办布局，3 项均通过：按钮内容居中、不溢出、保持触控高度，徽标圆形、白字且位于文字上方、未越出侧栏。

预览使用局部 HTML 和占位键盘，不能证明微信原生渲染及真实手机输入法行为。Android／iOS 真机、系统大字体、不同输入法和横屏仍待实际验收；未运行全量测试或构建。
