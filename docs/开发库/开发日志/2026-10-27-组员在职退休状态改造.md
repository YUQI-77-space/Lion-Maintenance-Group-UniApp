# 组员在职退休状态改造

创建日期：2026-10-27。业务方案见[实施计划](../设计文档/2026-10-27-组员在职与退休状态实施计划.md)，当前接口见[组员管理](../../member-management.md)。本记录取代旧移出方案的当前实现说明，保留先前调查和初始化修复记录作为历史证据。

## 已实现

- users / proUsers 同步 employmentStatus（active / retired），旧记录默认在职，不批量迁移。状态切换与版本、审计日志同事务；保留角色、原投影 ID、历史任务、待办、全部 EWA 和手动工作量。
- 替换移出入口为编辑在职状态，名单默认在职，支持退休／全部。旧 removeTeamMember 返回410。角色只能 member 与 leader 互换，不能降为游客，管理员身份不能在此调整。
- 退休后只读：维修、志愿、值班、待办及 EWA 云入口拒绝退休写入；管理名单仅在职组长／管理员可访问。个人账号资料维护和消息阅读保留。
- 退休前检查未完成维修（申请人、主／附加受理人）、未结束或日期异常值班、未结束活动（创建者／参与者）。阻塞时返回列表，不交接、不强制迁移、不自动取消或结算。
- 新增责任的关键写入与退休事务共写 users.membershipWriteTime，防止退休与接单、增受理人、活动创建／报名／导入、选班、内部成员报修同时成功。
- 登录和角色还原保留状态，响应下发状态。本人退休／降权后成功请求可重放，仅返回相同操作者的同一结果；客户端刷新身份并离开管理。
- 维修、志愿、值班、待办和个人页面显示已退休标签；状态按当前身份补充到响应，不覆盖历史快照。退休成员从应急联系人及新任务部门通知中排除。
- EWA 排行、搜索、本人排名、批量汇总、管理目标及实际四表导出排除退休人员。移除名单首屏旧缓存，退休后不再发送排名请求，旧响应不能重新展示名单。
- 初始化脚本继续自动补建和保护 member_management_logs；退休调用者不能通过初始化入口执行写入。部署云函数本身不等于执行初始化，自动补集合由部署脚本完成。
