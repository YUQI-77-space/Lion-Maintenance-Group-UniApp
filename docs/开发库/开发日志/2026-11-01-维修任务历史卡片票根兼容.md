# 维修任务历史卡片票根兼容

创建日期：2026-11-01。状态：本地实现及 L1 显示分支验证完成，未上传、未发布、未做微信环境视觉验收。

## 原因与改动

维修任务列表原模板只为进行中任务保留静态撕痕，已完成、已取消以及只读待受理记录均没有票根分支。这是旧版展示约定造成的遗漏，不是历史记录缺少迁移字段。

本次仅补齐 `miniprogram/pages/team/maintenance/list/index.wxml` 和对应 WXSS，复用既有 96rpx 票根、撕痕及语义 Token：

| 状态 | 当前展示 |
| --- | --- |
| 待受理、可写 | 保留认领入口与现有撕票动画 |
| 待受理、只读 | 静态「待受理」票根，无认领事件 |
| 进行中／已完成 | 直接呈现静态撕痕，无须曾播放动画 |
| 已取消 | 中性「已取消」静态票根，无认领事件；不推断是否曾被受理 |
| 未知／缺失 | 保留原未知状态回退，不推断为已受理或可认领 |

静态票根不呈现按钮按下态；状态标签继续显示。历史记录不补播动画。首屏、分页、分类及离线缓存均走同一模板，无须清缓存或新增展示版本字段。本次不修改 JS、云函数、权限、认领时序、业务状态、时间、受理人和工作量，不读取或写入云数据。

依据：[组件规范](../../知识库/Design/02-组件规范.md#4-卡片列表与功能入口)、[关键交互流程](../../知识库/Design/04-关键交互流程.md#4-维修任务受理执行与完成)。同步调整组件规范的历史终态约定；此前记录保留其历史含义。
