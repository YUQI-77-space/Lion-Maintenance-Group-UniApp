# 消息页紧凑列表调整

创建日期：2026-10-25。属于前端设计重构阶段 5／9 的个人消息页展示调整。

## 实际改动

- 顶部统计、未读计数与操作统一垂直居中；删除计数胶囊与操作分隔线。操作使用原生按钮，保留 48px 最小热区、8px 按钮间距，全部已读后禁用对应按钮。
- 消息改为连续白底列表，以细灰线分隔，删除卡片圆角、卡片间距、类型字块、彩色未读背景及发光圆点。
- 每行保留标题、完整分钟时间与一行摘要；通过灰点和标题字重区分未读。长标题与摘要省略，点击仍可读取完整标题、正文、分类和时间。
- 详情头部删除彩色类型字块与标签底框，关闭按钮改为中性色原生按钮；空状态删除装饰性圆底。
- 使用独立的消息行、标题和操作类，避免公共卡片规则覆盖局部布局。保留工作区原有设计 Token 调整，未修改消息 JS、云函数、业务 action 或数据。

## 依据

遵循用户指定的白灰、紧凑、去嵌套容器方向，以及 [组件规范](../../知识库/Design/02-组件规范.md)、[页面规范](../../知识库/Design/03-信息架构与页面规范.md) 和 [设计 Token](../../知识库/Design/design-tokens.json)。项目 ui-ux-pro-max 检索 `compact list text truncation`，采纳“摘要可截断但须保留完整详情入口”的通用建议。没有引入依赖或新的设计体系。

## 同日反馈修复：顶部统计被挤成竖列

用户提供原生截图，显示顶部两个按钮占据过宽区域，使统计逐字换行。上次只验证静态编译，未覆盖微信原生按钮默认宽度，此前实现存在布局缺陷。

- 两个操作按钮显式使用 `size="mini"` 和 `width: auto`，保留最小 48px 热区。
- 统计区禁止收缩、禁止文字换行；操作区保持内容宽度并靠右。超出容量时整组换行，避免把计数字符逐个挤开。
- 以现有 WXML、展开导入的 WXSS 创建浏览器映射，额外模拟普通按钮 184px 默认宽度；320／375／430／768px 与正常计数、无未读、9999 长计数组合共 12 组预检通过：统计一行、工具条不增高、无横向溢出、按钮至少 48px，统计与按钮中心对齐。已查看 375px 映射截图。
- 修复后官方 WXML、展开导入后的 WXSS 编译及差异空白检查通过。
