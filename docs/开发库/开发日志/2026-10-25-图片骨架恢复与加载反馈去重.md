# 图片骨架恢复与加载反馈去重

创建日期：2026-10-25。属于前端改造阶段 2、5 的公共图片展示与首页相册修正。

## 实际改动

按用户反馈恢复图片骨架，不再将统一 loading 动画用于每张图片等待。

- `skeleton-image` 移除占位层内的 loading 动画及组件注册，保留原固定尺寸灰底骨架、单图完成即展示、淡入、换源重置和失败回退逻辑。
- 首页特色活动、团队风采、团队荣誉三个图片区域移除区域动画。特色活动初始骨架补齐一大两小布局；荣誉骨架明确为与真实卡片一致的 240rpx 高度，避免父级未指定高度时占位塌陷。
- 特色活动及团队风采“更多”相册在首次请求时显示四张同布局骨架；逐图等待复用静态骨架。只有非刷新分页请求显示一处底部动画；下拉刷新时不再同时显示底部动画或初始化骨架。
- 公共头像删除逐张 loading 动画，复用已有头像轮廓占位，避免成员列表出现一排等待动画；清理相应注册及失效样式。
- 组件规范补充“同一次页面加载尽量只保留一处主动画”，明确图片骨架与头像轮廓占位为例外。此规则取代此前实施记录中将图片等待也统一为动画的设计选择；历史记录保留。

本次未修改 JS、接口、数据、权限或请求状态机。核对源码发现首页全局等待调用用于任务完成操作，而非图片初始化；两个相册未主动调用全局等待。因此本次保留全局等待挂载，不移除必要操作反馈。
