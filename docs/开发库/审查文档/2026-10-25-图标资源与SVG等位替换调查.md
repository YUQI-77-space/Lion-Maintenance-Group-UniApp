## 2. 调用链与替换边界

- 功能图片：`config/icons.js` → `utils/iconManager.js` → 页面 data → WXML `<image>`。配置与图片均被 Git 忽略，但本地可读；Git 忽略不等于小程序打包忽略。`project.config.json` 的 `packOptions.ignore` 当前为空，实际入包与压缩后体积仍须由开发者工具确认。
- TabBar：`iconManager.getTab()` → `utils/router.js` → 全局角色化 tabs → `custom-tab-bar/index.wxml` 的两张 `<image>`；`app.json` 还直接声明 8 个 PNG 路径。`pages/startup/index.js` 使用 `wx.getImageInfo` 预加载它们。不能仅修改映射后就删除全部 PNG，也不能把 `<image>` 可显示推导为所有平台接口均支持。
- 已有 SVG：`search.svg` 用于公共 `search-field`，具有原生 `icon type="search"` 回退；`members.svg`、`logout.svg` 由 iconManager 返回；`trash.svg` 用于消息页。它们证明已有实现路径，不代表所有机型已验证。
- 图片失败回退：iconManager 的默认路径只处理配置缺项，不处理 `<image>` 的解码失败；若迁移 SVG，必要页面要显式验证错误处理。设计规范要求新增格式验证目标机型并保留可用回退。
- 云图片：`cloudImageManager` 管理首页照片、活动、荣誉和插画地址；这些云文件本身不随本地包打入。改云端照片格式不能直接解释成本地包体积节省，照片与证书也不适合矢量重绘。

## 4. 重点发现

### 4.1 27 张功能图标适合保持原图形替换

操作、信息类包括关于、加号、箭头、勾选、编辑、删除、加载、定位、锁、开锁、消息、人员、切换、待办、空状态；业务类包括日历、值班管理、维修、志愿、维修管理、志愿管理、EWA 管理、工具、维修手册和软件库。完整文件名与映射见上表 A 类。

优先复用 `iconManager` 和 `assets/icons/`，不引入图标库或前端依赖。`trash.svg` 可作删除图标的结构参考，但现有红色线性垃圾桶与 `icon-delete.png` 的深色实心图形不同，直接复用会改外观；`search.svg` 同样与旧 PNG 的色值/笔画不完全一致。严格等位需核对形状、粗细与颜色，不能把“语义相同”写成“外观完全相同”。现有业务图标包含实心、线性和组合图形，统一到规范的线性图标应作为设计迁移另外记录。

### 4.2 12 张清理候选

`close.png`、`export.png`、`icon-urgent.png`、`more.png`、`pig.png`、`ranking.png`、`refresh.png`、`schedule.png`、`search.png`、`相机.png`、`tabs/app.png`、`tabs/app_active.png`，合计 52,686 字节。实施前移除失效配置/未消费 data，并再次扫描动态调用、开发者工具编译与相关页面；本次未删除。

其中加号、关闭、箭头、三点、勾选、简单加载环也可用少量 WXSS 表达；原生 `<icon>` 可覆盖部分搜索/成功等语义，但形状不一定等位，选择时以实测总字节数和视觉一致性为准。不要以字符或 Emoji 假装得到固定外观图标。

### 4.3 非普通功能图标

- 首页四图实际是圣诞主题，与当前“我要报修/值班表/维修任务/志愿活动”标签并不对应。保留节庆外观可描成 SVG；改为业务图标建议单列设计调整，不能计为已确认等位替换。
- `logo.png` 为 6250×6250、45.8 KiB，像素尺寸远超常见页面展示需要。遵守品牌规范，优先用官方源导出合适尺寸位图；如有官方矢量源可做页面显示专项评估。启动页分享 `onShareAppMessage.imageUrl` 也使用此 Logo，不宜全局改成 SVG 后假定分享接口兼容。
- `startup.png` 为 1032×2165 的复杂海报、147.6 KiB，占本地 PNG 字节约 37.4%。它是比小型操作图标更大的单项资源，可单独评估压缩、裁切和加载策略，不建议自动描摹成路径堆叠的 SVG。
- 默认头像是人形轮廓，技术上可矢量化，但只有 0.77 KiB，并被头像管理器与公共头像组件多处作为兜底；收益低于高频功能图标，真实头像不替换。

### 4.4 现存资源缺口

`config/icons.js` 声明 `other_time: time.png`、`status_music: music.png`，本地均不存在。`other_time` 被值班管理初始化并在自动切换设置弹窗 `<image src="{{iconTime}}">` 使用，可补简单时钟 SVG；这是修复缺图，不属于现有 PNG 替换收益。`status_music` 未见调用。`cloudImageManager` 还有 `/images/placeholders/` 兜底路径，本地目录不存在，属于另一个资源缺口，不能计入现有图片体积。

## 5. 建议顺序与验证要求

1. 核查并清理 12 张 D 类候选；先获得无需重绘的收益。
2. 迁移 27 张 A 类，逐张比较 SVG/PNG 字节数，保留尺寸、原图形和状态；对极小 PNG 不承诺转换收益。需要调整到品牌 Token 时单独标明视觉变化。
3. 单独处理 8 张 TabBar：自定义组件与 app.json 双链路、角色切换、普通/激活态和启动预加载一起验收。是否保留/移除配置中的可选图标字段需按官方配置说明与当前开发者工具编译确认，不预设 SVG 可以直接用于原生 iconPath。
4. 对首页节庆图、Logo 和启动海报分别决定描绘、设计调整或位图优化。

采用外置纯 SVG 文件供 `<image>` 加载，不假定 WXML 支持内联 Web `<svg>` 标签；不在每个页面重复嵌入 Base64，不把 PNG 编码后包在 SVG 内声称完成矢量化。保持 `width/height/viewBox` 明确，使用基础 path/几何图形与固定颜色，避免脚本、外链、字体和复杂滤镜。WXSS 本地背景图限制另行遵守，当前主链路本身使用 `<image>`。

后续实际替换须先按仓库要求核对当前微信开发者工具 CLI 的 `--help` 与官方文档，再编译并核对包资源明细；验证 iOS/Android 目标微信环境、图片加载失败表现、离线显示、明暗底对比、加载旋转、Tab 角色和选中态、分享图。PNG 留在包内作为回退时，不能把它的原大小算成已节省空间；最终收益为移除 PNG 减新增 SVG、回退与代码的实际打包差额。

## 6. 证据与限制

- 已验证：本地文件数量、字节数、像素尺寸、图像缩略总览；图标配置→管理器→调用→模板链路；`loading.png` 与 `refresh.png` 字节完全相同；图片/配置被 Git 忽略；已有 SVG 的引用路径。
- 未验证：SVG 成品外观与大小、微信编译和真机显示、兼容性回退、实际上传包节省。本次只有调查文档新增，无运行时代码或图片改动，因此未运行编译、自动化或占位 npm test。
- 已读取 ponytail、项目 ui-ux-pro-max Skill、设计索引、视觉规范相关约束、小程序适配规则与设计 Token。Skill 图标库对 `consistent svg icons` 与 `search` 两次检索均无匹配；本报告依据仓库真实图形和调用链，不使用未命中数据作为选型依据。
- 尝试读取微信官方 [image 组件说明](https://developers.weixin.qq.com/miniprogram/dev/component/image.html) 和 [app.json 配置说明](https://developers.weixin.qq.com/miniprogram/dev/reference/configuration/app.html)，当前检索服务均返回不可打开。故本次不将平台全场景 SVG 兼容性列为已核实结论，实施前仍需官方说明与实际验收。
