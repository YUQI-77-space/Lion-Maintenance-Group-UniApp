# 上线前体积与冗余代码调查

创建日期：2026-10-27。范围：调查时的本地工作区，包含未提交文件，以及本地实际存在、被 Git 忽略的 `miniprogram/images/`、`miniprogram/config/`。状态：只读代码调查完成；本轮仅新增本文，未删改业务代码、资源、依赖或配置，未部署、上传或发布。

## 1. 结论与口径

当前项目存在可清理的组件、资源、方法及旧弹窗，但前端没有发现整套闲置框架或大型第三方依赖。体积不能用仓库大小、云函数依赖大小或源码行数代替。

- 前端：确认 1 个未使用组件、13 张无当前业务调用的图片、44 个无入口方法或随无入口界面一起清理的方法；另有一套旧权限确认弹窗。合计约 **70.0 KiB 原始文件／代码文本**，不含关联注释、配置行、字段和样式清理。
- 样式：存在未引用的旧页面样式、公共工具类，以及后追加的覆盖规则；应单独整理，不把字符串扫描候选直接当作可以删除的完整集合。
- 后端：EWA 云函数的 `exceljs` 没有源码调用，旧 `exportExcel.js` 实现也没有分发入口。前者本地安装目录约 **20.9 MiB**；按锁文件估算，独占依赖链约 **30.0 MiB**。这是云函数部署侧收益，**不减少小程序客户端包体**。
- 主包：30 个页面全部在主包，没有分包。分包有机会降低首次下载量，但属于结构调整，不能计作删除冗余代码。

所有体积均按实际文件字节统计，`1 KiB = 1024 B`。未取得本次微信编译后的主包／上传包明细，本文不承诺编译包能按源码字节数等量减少；已被工具过滤的文件、压缩、导入展开及编译产物都会影响净收益。
