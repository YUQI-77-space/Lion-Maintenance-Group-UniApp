# 全项目短文案容器对齐检查与修正

## 范围与结论

针对用户反馈的待办按钮下方留白、“已退休”标签纵向偏上，遍历全部 48 份 WXSS，检查原生 button、按钮类 view、状态／身份标签、徽标、筛选项及绑定点击事件的其他入口，并追踪公共样式与局部覆盖。通过 WXML 提取和人工补查，纳入局部布局验证的短文案容器共 137 种用法，分布在 33 个页面／组件视图；同一语义类在不同页面分别计数，此数字不是业务状态总数。

根因有三类：父级 flex 默认拉伸紧凑标签；公共最小点击高度增加后局部文字仍按普通文档流定位；旧按钮以固定 rpx 行高定位文本，和最小 px 高度不一致。

## 已实现

仅修改 20 份样式文件，没有修改 JS、WXML、事件、权限、业务状态或接口。本记录不把先前其他任务的工作区改动归入本次。

| 范围 | 修正 |
| --- | --- |
| 公共退休标签 | 改为 inline-flex，内容双向居中，使用 `align-self: center` 防止横向信息行拉伸，字体／行高沿用 caption Token |
| 原生按钮与公共短动作类 | 设置实际内容居中；公共动作使用与字号相关的行高，覆盖旧整按钮高度行高；保留既有点击热区与语义色 |
| 状态标签 | 公共任务／活动状态使用自适应高度与居中对齐，防止随信息行拉伸 |
| 身份、来源与统计标签 | 修正角色、组员身份、组长创建、EW 角色与标题、值班编辑状态／统计等紧凑容器 |
| 筛选与分类 | 报修 chip、分类地图 type-chip、受理人抽屉部门筛选项增加实际居中方式 |
| 首页 | 进度状态与短动作居中；两类相册“已展示全部照片”的重复祖先选择器改为正确的单层祖先选择器 |

自定义 Tab、图标加文字入口、多行设置行、由父级居中的纯文本提示保留原有结构。已读取隔离组件样式；现有 action-modal、feedback-modal、search-field、count-badge、section-header 等组件的按钮／计数已有居中方式，无需为了统一而重写。将可复用规则补充到 Design 的 02-组件规范。

## 实际验证

使用项目 UI/UX Skill、Design 索引／组件规范／Token／小程序适配规则，检索紧凑标签换行问题，采用适合原生小程序的内容对齐建议。

验证停于 L2，不因样式文件数量升级到全量业务测试。没有运行测试占位入口、安装、构建或云资源操作。

1. L0：全量样式、WXML 与点击入口静态追踪，明确局部覆盖和样式隔离边界。
2. L1：Chrome headless 加载实际 WXSS 展开、换算 rpx 后的局部 HTML，3 个退休标签／待办按钮用法通过。退休标签放入较高的横向信息行，检查高度未被拉伸及文字中心位置。
3. L2：其余 133 种用法通过最终计算样式检查。验证原生按钮／单动作容器的内容居中、行高不过大，或由真实对应父容器负责居中。初始检查有缺少真实祖先结构的误报，核对原 WXML 后补全相应组件／页面祖先夹具；多按钮布局容器不作为单文字按钮参与断言。相册选择器确有错误，修复后验证通过。
4. 补查发现的部门筛选项单独在 320／375／430px 三种宽度检查，通过；未重跑已经覆盖且样式输入未变化的其他用法。最终唯一用法数为 3＋133＋1＝137。

浏览器探针与脱敏结果位于本次 Codex 可视化工作目录 `short-text-audit/`，未在仓库根目录散落脚本。测试夹具使用真实 WXSS 和简化的短文案／祖先结构，仅证明相应 CSS 对齐与退休标签几何，不是完整页面或微信渲染器验收。

尚未完成 Android／iOS 真机、系统大字体及所有动态文案、加载态的完整视觉验收。未将 137 种局部用法通过表述为全量业务或真实设备通过。
